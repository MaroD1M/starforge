## 0. 先说结论

1. **P0 已完成**：原生壳、服务层、五页导航、原生 3D 视口、任务线程、设置/诊断、`starforge app` 默认原生。
2. 接下来的功能分四条线，**不要混在一起做**：
   - **A 离线**：搜索、3D、存档、种子反查、银河索引、符文、飞船设计器、存档编辑器。
   - **B 游戏侧数据 Mod**：EXML 模板槽（已可用），只改“数据”，不注入代码。
   - **C 外部实时**：只读内存 / 模板槽写入（SSH 路线），够做“送进游戏”，做不了可靠的传送/扫描。
   - **D 进程内 agent**：pymhf 注入 Python Mod（NMSpy 提供结构体/函数签名），才能做**传送、扫描、任意建造、改色、解上限**。
3. **agent 不是可选项**：你要的“游戏内传送、扫描”必须走 D。C 只能做简单数据写入。
4. 预计工作量：**单人全职 3–5 个月**（含 Windows 实机校准轮次）。最不确定的是 D 线的函数签名/结构体偏移。

## 3. agent 是什么、为什么必须有

详见 `docs/AGENT.md`。一句话：

> **agent 是运行在 `NMS.exe` 进程内的小型 DLL。**
> 外部 Python 只能“看/改内存”，无法可靠调用游戏的 C++ 函数；
> agent 在进程内拿到函数地址和对象布局，才能执行传送、扫描、建造这类“操作”，
> 并把结果通过本机命名管道返回给 starforge。

没有 agent 时：
- ✅ 能改存档、搜种子、看 3D、读内存里的模板槽；
- ❌ 不能稳定“热传送”、不能调用游戏扫描函数、不能任意建造/改色。

## 6. 安全红线（不因“什么都能做”而取消）

1. **单人模式**：检测到其他玩家在线时，M5–M7 高风险命令全部禁用。
2. **不猜**：签名多候选且同样可信 → 拒绝写入；未知 build → 只读。
3. **可回滚**：写存档前备份 + 原子写 + 读回；agent 写内存前快照 + `restore`。
4. **默认关闭**：agent 安装、传送、扫描奖励、建造/改色都需要显式开启和二次确认。
5. **不做**：多人写入、在线反作弊规避、自动挂机/刷资源。
6. **可卸载**：agent 备份原 `winmm.dll`，卸载后完全还原。

## 7. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 游戏更新改签名/偏移 | 传送/扫描失效 | build 地址书 + 多候选 + 未知 build 只读 |
| 运行时注入导致崩溃 | 游戏退出/存档风险 | 只写快照、先只读、逐步开能力、失败即 restore |
| 杀软误报 | 注入被拦 | 开源、默认不装、应用内可停用 |
| NMSpy 版本与游戏不匹配 | 结构体/签名错位 | 应用自动识别 build 并安装对应 NMSpy 版本；不匹配时只读/拒绝写 |
| 外部内存写不可靠 | 传送失败/卡死 | 传送只走 agent，不用外部写世界状态 |
| 全功能范围过大 | 延期 | 按 P1→P2→M4→M5→M6→M7 分阶段，每阶段可停 |
