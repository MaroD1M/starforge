# Starforge Command Deck · 社区 UI/UX 研究与路线图

> 性质：纯研究与设计文档。本文不改代码、不提交、不构建。
> 目标：在现有 PySide6 Command Deck 上，形成“专业桌面工具优先、无人深空元素可选”的 UI/UX 方案。
> 依据：`docs/UI-REDESIGN.md`、`docs/FEATURE-MAP.md`、`docs/ARCHITECTURE.md`、`starforge/app/pages/*`、`starforge/app/widgets/*`，以及 NMSCoordinates、NMSSaveEditor、NMS.py/NMSPY、NMSCD/nmsce、NoMansConnect、NMS Companion 等社区项目的公开资料。

---

## 0. 结论先行

1. **先做“专业工具”，再加“无人深空氛围”。** 社区工具真正被长期使用的是搜索、筛选、坐标转换、存档备份、批量操作和错误恢复，不是皮肤。
2. **当前最大缺口不是视觉，而是状态与结果管理。** 搜索结果仍是 `QListWidgetItem` 流式填充，缩略图回调用 `QTimer` 串行排队，缺少取消、代际校验、虚拟化和统一任务模型；筛选条件只是一行 `QLabel` 文本，不是可编辑对象。
3. **把“条件、结果、任务、错误”变成一等公民。** 条件用可删除/可拖拽 chip；结果用 model/view；任务用统一 JobService + JobDock；错误统一为“原因 + 下一步 + 重试”。
4. **坐标/符文是 Starforge 的差异化能力，应做成专业转换器。** 参考 NMSCoordinates 的“坐标计算器 + 点击符文填入 + 备份后改档”，但不要复制其 WinForms 布局。
5. **NMS 元素只放在“氛围层”，不进入“数据层”。** 配色、等宽字体、低透明度扫描线、3D HUD 角标、游戏原版符文图标可以加分；全屏拟物、持续动效、CRT 滤镜、游戏字体正文必须禁止。
6. **桌面交互要补齐键盘、右键、多选、批量、焦点、DPI、可访问性。** 这些是桌面工具与网页后台的分水岭。
7. **不重复造轮子。** 优先使用 Qt 自带的 model/view、proxy、QSettings、QAction、QUndoStack、QAccessible、QPropertyAnimation；不引入 DearPyGui、Electron、pandas、主题库或图标包。

## 1. 研究方法与边界

- 阅读现有文档与实现，记录页面、组件、异步路径和占位功能。
- 只研究社区项目的**交互模式与信息架构**，不复制代码；涉及 GPL 等许可证的项目只做行为参考。
- 社区项目版本、NMS 版本和截图会变化，本文结论以“可迁移的交互原则”为准，不把某个按钮位置当成标准。
- 所有建议默认离线、只读优先、写操作必须备份；不引入联网同步作为默认能力。

### 1.1 社区项目速览

| 项目 | 类型 | 最值得看的部分 |
|---|---|---|
| NMSCoordinates | 桌面坐标/传送工具 | 存档槽选择、基地/空间站列表、坐标计算器、点击符文填入、启动自动备份、改档后提示重载存档 |
| NMSSaveEditor | 桌面存档编辑器 | 明确的存档槽与备份流程、按对象分页、拖放/右键物品管理、原始 JSON 作为高级页、风险提示 |

## 2. 社区项目值得借鉴的交互

### 2.1 搜索与筛选

**值得借鉴**

- **点击部件图筛选**（nmsce）：把“部件”变成可识别的视觉对象，而不是只让用户记 ID。Starforge 已有部件树和缩略图，应把“勾选”升级为“加入想要/不要条件”，并显示已选条件。
- **条件可叠加且有上下文**（nmsce / NoMansConnect）：时间、星系、系统、名称、标签、距离、基地等条件并列显示；Starforge 应把船型、部件、涂装、预算、来源统一到一条“条件条”。
- **搜索语法/前缀**（NoMansConnect 的 `tag:lush`）：对高级用户有价值，但应作为可选补充，不替代可视化筛选。
- **排序与分组**（NoMansConnect、NMS Companion）：按类型、等级、距离、最近、收藏分组；Starforge 的 Fleet/Galaxy 目前几乎没有排序。
- **结果即时刷新与计数**：筛选变化后立刻显示“命中 N 条”，而不是等用户点按钮才知道。

**不要照搬**

- 不要把筛选做成一大排下拉框塞在表格下方；桌面端应使用可折叠的 FilterBar + chip 摘要。
- 不要只提供自由文本搜索；部件 ID、中文名、种子、坐标需要不同的匹配策略。

### 2.2 坐标与符文

**值得借鉴**

- **坐标计算器**（NMSCoordinates）：银河坐标 ↔ 传送门地址 ↔ Voxel X/Y/Z/SSI 互转；同时显示 HEX/DEC，避免用户自己换算。
- **点击符文填入地址**（NMSCoordinates、NMS Coordinate Tool）：12 个符文位置可视化，点击即填；比手打十六进制可靠。
- **只读展示 + 复制**：Glyphs、Galactic Coordinates、Portal Code、Voxel 分列显示，每项独立复制。
- **改档后明确下一步**（NMSCoordinates）：写完后提示“回到游戏重载存档”，而不是只显示“成功”。
- **首符文特殊性与非法值校验**（NMSSaveEditor 的坐标查看器）：第一符文、银河编号、坐标范围要校验；非法值可能导致崩溃或落到太空。
- **导入/导出坐标 JSON**：便于分享和复现；Starforge 可先做本地文件，不默认联网。

**Starforge 的落点**

- Galaxy 页增加“地址工作台”：输入符文/坐标/种子，输出另一侧；支持从剪贴板粘贴、复制、最近记录、置顶浮窗。
- GameLink 传送前必须先经过同一套校验，并显示目标星系/行星摘要，而不是只让用户填 12 位字符串。

### 2.3 存档编辑

**值得借鉴**

- **先选槽位，再编辑**（NMSSaveEditor）：打开存档时明确当前槽位、备份路径、只读/可写状态。
- **自动备份 + 可恢复**（NMSSaveEditor、NMSCoordinates）：启动/写入前备份，备份列表可查看时间、大小、来源，可一键恢复。
- **按对象分页，而不是一张大表**：飞船、货船、护卫舰、多用途工具、同伴、定居点各自有上下文。
- **拖放与右键管理**（NMSSaveEditor）：同容器拖放、跨容器右键移动、Ctrl+拖拽克隆；Starforge 的批量导出/对比可借鉴其“先选对象，再选动作”。
- **原始 JSON 只作为高级页**：默认界面不暴露底层结构；高级页明确“一次只改一块、先备份”。
- **风险与上限提示**：超出原版槽位、跨型移植、非法值必须有前置警告，而不是失败后抛异常。

**Starforge 的落点**

- Fleet 的“备份/恢复”从禁用按钮升级为真正的备份管理器。
- 写回对话框保留“副本写入”，并增加“目标槽位差异、备份路径、失败回滚说明”。
- 不做批量写回；批量只允许导出、收藏、复制等非破坏操作。

### 2.4 地图与列表

**值得借鉴**

- **列表与地图互补**（NoMansConnect）：列表负责精确筛选，地图负责空间感；不要只做其中一个。
- **2D/3D 两种地图层级**（NoMansConnect、NMS Companion）：总览 + 局部，而不是一上来就渲染整个银河。
- **卡片图鉴 + 表格对比**（NMS Companion）：浏览用卡片，比较用表格；Starforge 的 ShipLab/Fleet 已有卡片，缺可排序表格。
- **按区域/星系分组**（NMS Companion）：扫描结果多时，分组比无限列表更可读。
- **“最近核心”/距离信息**：对找星球和规划路线有用，可作为 Galaxy 的排序字段。

**不要照搬**

- 不要把 3D 星图作为默认首屏；先保证表格、筛选、复制地址可用，再考虑地图。
- 不要为了地图引入 Three.js/Electron；Qt 的 `QPainter`/`QOpenGLWidget` 足够做轻量星图。

### 2.5 状态反馈

**值得借鉴**

- **明确的状态机**：未连接 → 运行时就绪 → 已注入 → 已进入存档；每一步都有解释和下一步按钮。
- **持久反馈，而不是一次性弹窗**：任务完成后在 Dock/Toast 保留结果，用户离开页面也能看到。
- **自动恢复提示**：写档后提示重载；备份后显示备份路径；失败后显示“下一步”。
- **外部状态可见**：游戏是否运行、存档是否变化、agent 是否可达，用状态芯片 + 时间戳表达。
- **错误可复制**：诊断信息、任务错误、agent 日志都能一键复制，方便求助。

**Starforge 的落点**

- 引入 `Toast`、`EmptyState`、`ConfirmSheet`、`JobDock` 四个统一反馈组件；页面不再各自用 `statusBar().showMessage` 或 `muted` 标签承担全部反馈。

### 2.6 键盘

**值得借鉴**

- **全局命令面板**：`Ctrl+K` 打开，输入即筛选，Enter 执行，Esc 关闭。
- **对象级快捷键**：列表内方向键移动，Enter 打开，字母键执行常用动作。
- **全局热键要克制**：NMS Companion 的 `Alt+C`/`Alt+S` 很强，但桌面工具不应抢占游戏热键；只做应用内快捷键。
- **快捷键可发现**：命令面板和右键菜单显示快捷键；提供 `F1`/`Ctrl+/` 速查表。
- **注意平台限制**：pyMHF 的按键绑定能力有限（复杂组合键不可用），不要把游戏内热键设计成应用的核心路径。

### 2.7 空态与首次使用

**值得借鉴**

- **首次使用清单**（NMSSaveEditor 的安全编辑清单）：确认路径 → 备份 → 单次修改 → 游戏内验证。
- **空态即入口**：没有存档时给“自动检测/选择存档/打开设置”，没有结果时给“放宽条件/换船型/提高预算”。
- **失败态保留上下文**：搜索失败不清空上一次结果；读取存档失败保留路径输入。
- **占位功能明确标注**：未实现功能要么隐藏，要么显示“计划中 + 原因”，不要放一个点了没反应的按钮。

### 2.8 不要借鉴的部分

- 过度依赖弹窗确认（每次操作都弹窗会让高频流程变慢）；只在破坏性/不可逆操作使用模态确认。
- 把原始 JSON/日志作为主界面；高级信息应折叠。
- 用大量颜色区分状态而没有文字/图标；色盲用户无法判断。
- 把游戏内 HUD 的视觉密度直接搬到桌面表格；游戏 HUD 是远距离可读，桌面是近距离高密度，两者不同。

## 3. 当前实现审查（证据与影响）

### 3.1 已有优势

- Shell 已有 CommandBar、NavRail、Workspace、JobDock 的雏形，方向正确。
- ShipLab 已打通“条件 → 搜索 → 缩略图 → 3D → 写回对话框”的主链路。
- Galaxy 已有行星/船池/扫描三个视图，且有符文 PNG 能力。
- GameLink 已能展示运行时/Mod/Agent 三段状态，并有安全区意识。
- 主题已统一为深色 QSS，且有自定义飞船卡片 delegate。

### 3.2 主要缺口

| 区域 | 证据 | 影响 |
|---|---|---|
| 条件不可编辑 | `starforge/app/pages/ship_lab.py:105` 的条件只是 `QLabel`；`82` 用全局“想要/不要”下拉切换 | 用户看不到结构化的想要/不要，无法单独删除/排序 |
| 结果不是模型 | `ship_lab.py:160` / `fleet.py:77` 直接向 `QListWidget` 塞 item | 难排序/过滤/虚拟化；多选与批量操作难做 |
| 异步缩略图有竞态 | `ship_lab.py:30,419` 队列持有 `QListWidgetItem`；清空结果后旧回调仍可能执行 | 可能写回已销毁 item，出现崩溃或错图 |
| 任务不可取消 | `job_dock.py:48` 只轮询展示；`worker.py` 无取消/代际 | 用户只能等；切换条件后旧任务继续跑 |
| 反馈单薄 | 多数页面用 `statusBar` 或 `muted` 标签；无 Toast/EmptyState | 错误一闪而过，空态没有下一步 |
| 主题与文档不一致 | `theme.py:21` 使用蓝色高亮；`UI-REDESIGN.md` 定义琥珀/青 | 视觉方向漂移，NMS 氛围没有形成体系 |
| 符文复制脆弱 | `galaxy.py:192` 通过拆分 `badge.text()` 的 `·` 取符文 | 文案一变就复制错 |
| 扫描结果只末尾填充 | `galaxy.py:238` 完成后一次性写表 | 长扫描无渐进反馈，用户不知道是否卡住 |
| 占位按钮可见 | `fleet.py:54,73,100`、`ship_lab.py:207,223`、`settings.py:85` | 用户点击无反馈，像坏掉 |
| 无右键/多选/批量 | 全页面未见 `QMenu`/`contextMenuEvent`/多选批量条 | 与专业桌面工具差距明显 |
| 无焦点/可访问性体系 | 未见 `setAccessibleName`；自定义 delegate 无替换文本 | 键盘/读屏用户无法完整使用 |
| 布局记忆不完整 | `shell.py:238` 只存窗口 geometry | Splitter、Rail、Dock、Inspector 宽度每次重置 |
| 命令面板较弱 | `command_palette.py:37` 仅子串匹配，无分组/最近/对象搜索 | 只能当导航菜单，不能当效率入口 |

### 3.3 需要优先消除的风险

1. **异步代际问题**：搜索/扫描/缩略图/3D 预览都需要 `generation` token 或 `job_id`，回调先校验再落地。
2. **写操作状态机**：写回对话框当前在 `write_back.py` 内完成备份/写入/读回，但没有把“正在写/已备份/校验失败/已回滚”呈现为可视步骤。
3. **占位功能语义**：禁用按钮没有 tooltip 解释；应统一为“禁用 + 原因 + 计划版本”或直接隐藏。
4. **主题漂移**：新增颜色继续散落在 QSS 和 `setStyleSheet` 字符串里；应先建立 token。

## 4. 页面改进清单

> 每条按“布局 / 组件 / 交互 / 状态 / 验收标准”给出。验收标准默认包含 1366×768 与 1920×1080 两档。

### 4.0 全局 Shell（跨页面）

#### G1. 导航栏改为“图标 + 短标签”，并保留快捷键

- **布局**：左侧 64–72px Rail；顶部品牌/版本；6 个一级入口；当前项用 2px 琥珀竖线 + 背景高亮；底部放连接状态与设置。
- **组件**：`NavRail`、`NavButton`（图标 + 10–11px 标签 + tooltip）、`StatusDot`。
- **交互**：点击切换；`Ctrl+1..6` 直达；`Tab` 可聚焦；当前页有 `accessibleName`；图标可键盘触发。
- **状态**：正常/悬停/选中/键盘焦点/禁用（如 agent 不可用不禁止导航，只提示）。
- **验收**：1280×720 下 Rail 不挤压主内容；键盘可完成 6 页切换；选中态不依赖颜色单独表达（竖线 + 背景 + 文本加粗）。

#### G2. Command Bar 成为真正的全局状态栏

- **布局**：左侧面包屑；中间当前任务摘要；右侧数据/存档/游戏/写入四个状态芯片 + 通知入口 + 命令面板入口。
- **组件**：`Breadcrumb`、`StatusChip`（图标 + 文本 + 状态）、`NotificationButton`、`CommandButton`。
- **交互**：点击状态芯片跳到对应页面/设置项；悬停显示最近一次检查时间；`F5` 刷新；写入状态点击打开写入说明。
- **状态**：未知/检查中/正常/警告/错误；芯片带“上次检查 12:34:56”；长任务时中间显示进度。
- **验收**：任一芯片都能用一次点击到达可修复页面；状态变化 300ms 内有视觉反馈；不会出现“写入已开=绿色”这类语义反转。

#### G3. JobDock 统一任务、可取消、可定位

- **布局**：默认只显示一行标题（进行中数量 + 最近任务 + 展开按钮）；有任务时自动展开到 2–4 行；详情可滚动。
- **组件**：`JobDock`、`JobRow`（状态图标、名称、进度、ETA、取消、定位）、`JobEmpty`。
- **交互**：点击任务跳到发起页；`Cancel` 取消；`Ctrl+Shift+J` 展开/收起；错误行可复制详情；完成后保留 10 分钟。
- **状态**：空闲/排队/运行/成功/失败/已取消；失败行红色 + 原因 + 重试；取消中显示“正在停止”。
- **验收**：搜索/扫描/写回/注入都能在 Dock 看到并取消；离开页面任务继续；取消后 2 秒内不再有旧回调更新 UI。

#### G4. 命令面板升级为“对象 + 命令”入口

- **布局**：顶部输入框，下面分组列表（最近、导航、当前页动作、对象）；底部显示快捷键提示。
- **组件**：`CommandPalette`、`CommandGroup`、`CommandRow`（标题、副标题、快捷键、图标）。
- **交互**：`Ctrl+K` 打开；模糊匹配（连续字符/拼音首字母可选）；↑↓ 选择；Enter 执行；Esc 关闭；无结果时显示“试试：找船 / 我的船队 / 123456789ABC”。
- **状态**：空输入显示最近 5 条；无结果显示空态；执行后关闭并聚焦目标控件。
- **验收**：输入“找船”“fleet”“设置”都能命中；对象搜索（种子/星系名）可在 2 次按键内到达；完全键盘可用。

- **布局**：右侧详情：坐标、符文、群系、天气、哨兵、资源、经济、冲突、距核心；底部动作。
- **组件**：`ScanDetail`、`GlyphBar`、`NextActions`。
- **交互**：复制全部；复制符文/坐标；传送到此；置顶；导出单条。
- **状态**：加载/完整/字段缺失/错误。
- **验收**：用户从结果到“复制地址/传送”不超过 1 次点击；缺失字段显示“未知”而不是空白。

#### Y6. 银河索引查询与虚拟表格

- **布局**：独立 Tab 或抽屉；顶部搜索/条件；结果用虚拟表格；底部导出。
- **组件**：`GalaxyIndexModel`、`GalaxyIndexProxy`、`QueryBar`。
- **交互**：输入即查/点查询；保存查询；分页或增量加载；`Ctrl+E` 导出当前筛选。
- **状态**：未查询/查询中/无结果/失败；大结果集显示总数与已加载数。
- **验收**：查询不一次性加载全部索引；导出只导出当前筛选；无结果给“放宽条件”。

#### Y7. 符文置顶浮窗

- **布局**：独立无边框窗口，符文条 + 地址文本 + 关闭/穿透/缩放。
- **组件**：复用 `starforge/app/overlay.py` 的 `GlyphOverlay`，增加从 Galaxy 直接调用的入口。
- **交互**：置顶/点击穿透/拖动/`Esc` 关闭；记住位置与缩放。
- **状态**：显示/隐藏/穿透/错误（无符文）。
- **验收**：从 Galaxy 一键置顶；不抢游戏焦点；多显示器位置合理。

### 4.5 GameLink 游戏内通道

#### L1. 三步状态机可视化

- **布局**：顶部三张步骤卡（运行时 / Mod / Agent），每张包含状态、说明、主按钮、详情展开。
- **组件**：`AgentStep`、`StepStatus`、`StepDetail`。
- **交互**：每步可单独重试；失败步骤展开原因；成功步骤折叠为一行；下一步按钮高亮。
- **状态**：未检查/检查中/就绪/缺失/失败/不支持；每步有“为什么需要”说明。
- **验收**：用户能明确知道卡在哪一步、下一步点什么；不再把三个 chip 当成状态机。

#### L2. 能力/版本矩阵

- **布局**：连接卡下方一张表：能力（传送/扫描/船槽/还原）、支持状态、版本要求、说明。
- **组件**：`CapabilityMatrix`、`BuildBadge`。
- **交互**：从 agent `hello` 读取；不支持项禁用并显示原因；build 不匹配时置顶警告。
- **状态**：支持/部分支持/不支持/未知；版本匹配/不匹配。
- **验收**：UI 不硬编码能力；不支持的操作不会显示为可点击；版本不匹配有明确升级/降级建议。

#### L3. 实时遥测面板

- **布局**：玩家 UA、位置、当前星系、当前行星、船槽数量；每项为可复制字段；右上角“自动刷新”开关与时间戳。
- **组件**：`TelemetryGrid`、`CopyField`、`AutoRefreshToggle`。
- **交互**：连接后自动拉取一次；可手动刷新；自动刷新间隔可选；复制单项/全部。
- **状态**：未连接/加载/正常/过期/失败；过期时字段变灰并显示“最后更新”。
- **验收**：不再需要逐个点四个按钮才能看全状态；自动刷新可关闭；失败不清空上次数据。

#### L4. 安全区重新设计

- **布局**：传送、扫描、还原分成三张独立卡；每张卡显示“会发生什么 / 前置条件 / 备份 / 如何还原”。
- **组件**：`DangerActionCard`、`PreflightChecklist`、`ConfirmSheet`。
- **交互**：传送前先显示目标摘要（来自 Galaxy/地址工作台）；高风险操作需勾选“已备份”或输入确认词；还原单独确认。
- **状态**：未满足前置/可执行/执行中/成功/失败/已还原；失败显示回滚结果。
- **验收**：任何高风险操作在点击前都能看到影响范围；即时扫描开关也需确认；失败有恢复路径。

#### L5. 结构化日志查看器

- **布局**：日志卡占页面下半部；顶部级别筛选、搜索、暂停自动滚动、复制、保存、清空。
- **组件**：`LogView`、`LogFilter`、`LogLevelBadge`。
- **交互**：`Ctrl+L` 聚焦；`Ctrl+Shift+C` 复制；按级别/关键词过滤；JSON 默认折叠为摘要，可展开。
- **状态**：空/跟随/暂停/过滤无结果/错误。
- **验收**：日志不再是整段缩进 JSON；用户能快速定位错误；复制内容包含时间/级别/上下文。

#### L6. 每动作忙碌与错误恢复

- **布局**：每个按钮旁可显示小型 spinner；页面顶部显示当前动作；错误内联在对应卡片。
- **组件**：`BusyButton`、`InlineError`、`RetryAction`。
- **交互**：只禁用当前动作；失败后立即恢复按钮；错误提供“重试/复制详情/打开日志”。
- **状态**：空闲/执行中/成功/失败/超时；超时有重试与取消。
- **验收**：不会出现按钮永久禁用；错误不依赖 `QMessageBox` 才能看到；重复点击不会并发执行。

### 4.6 Settings 设置与诊断

#### T1. 表单脏状态与校验

- **布局**：路径、数据、外观、性能、高级五组；每组可折叠；底部固定“保存/还原”栏。
- **组件**：`SettingsForm`、`PathField`（输入 + 浏览 + 校验图标）、`DirtyBar`。

- **验收**：不再出现“勾选写入立即保存”的隐式行为；非法路径不能保存；错误定位到具体字段。

#### T2. 写入安全开关

- **布局**：独立卡片，显示当前是否允许写入、影响范围、最近写入时间、备份位置。

#### T3. 诊断结构化展示

- **状态**：未运行/运行中/全部通过/有警告/有错误。
- **验收**：用户不必读整段 JSON 就能知道问题；复制内容可直接贴到 issue；修复入口可点击。

#### T4. 诊断包导出

## 5. NMS 元素的使用边界

### 5.1 总原则

- **氛围层与数据层分离**：颜色、背景、扫描线、HUD 角标可以变；表格、文字、焦点、错误信息不能为了“像游戏”而牺牲可读性。
- **默认轻量，可选沉浸**：默认“轻”氛围；设置里可关闭或增强。
- **动效只表达状态**：加载、扫描、连接、写入；不做无意义常驻动画。
- **一切氛围效果可关闭**：减少动效/高对比/低性能模式优先。

### 5.2 可以增强氛围的元素

| 元素 | 建议用法 | 边界 | 验收 |
|---|---|---|---|
| 配色 | 深空底 `#070A10/#0B0F16`；面板 `#0F141D`；琥珀 `#F2B45C` 用于主强调/选中；青色 `#5AD7FF` 用于焦点/链接/扫描 | 正文不用高饱和琥珀/青色；危险色只用于危险；不要整屏蓝紫渐变 | 正文对比度 ≥ 4.5:1；状态不靠颜色单独表达 |
| 字体 | UI：Microsoft YaHei UI / Segoe UI；数据：Cascadia Mono / Consolas（种子、坐标、符文、版本） | 游戏字体只用于品牌/大标题，不用于正文和表格 | 11–13px 正文可读；等宽字段对齐；不出现字体缺失回退错乱 |
| 扫描线 | 仅 3D 视口/Hero 背景；静态或 ≤1fps；透明度 2–5%；默认关闭或“轻” | 不覆盖表格、正文、按钮；不做滚动扫描线 | 关闭后无残留；开启不影响阅读；GPU/CPU 无明显开销 |
| HUD | 3D 视口四角细角标、坐标/种子小标签、选中目标环 | 不包围整个页面；不遮挡模型；不模拟游戏内全屏 HUD | 角标不拦截鼠标；缩放/DPI 下不变形 |
| 图标 | 单色线性图标（1.5px），与文字基线对齐；符文使用游戏原版贴图 | 不用彩色游戏物品图标做导航；不用 emoji 代替图标 | 图标在深浅背景都可辨；有 tooltip/accessibleName |
| 星空/星图 | Home 空态/英雄区静态低对比星点；Galaxy 地图用点/线 | 不做视差滚动；不做全屏动态星空 | 不影响文字；低性能模式可关闭 |
| 声音 | 默认关闭；仅可选提示音 | 不模仿游戏 UI 音效；不自动播放 | 静音状态下无功能损失 |

### 5.3 不要做的元素

| 禁止项 | 原因 | 替代 |
|---|---|---|
| 持续背景动画/视差星空 | 分散注意力、耗电、低端机掉帧 | 静态星点或纯色渐变 |
| 开机/扫描 typewriter、glitch、CRT 滤镜 | 拖慢任务、降低可读性、显得廉价 | 150–220ms 状态过渡 + 进度条 |
| 游戏内拟物面板（大圆角、厚重边框、全屏橙黑 HUD） | 信息密度低，和桌面表格冲突 | 低饱和面板 + 细边框 + 清晰层级 |
| 用游戏字体做正文 | 小字号可读性差、中文支持不稳 | UI 字体正文 + 等宽字体数据 |
| 扫描线覆盖数据区 | 文字抖动/模糊 | 只在 3D/Hero 局部，且可关 |
| 过度发光/霓虹/屏幕震动 | 视觉疲劳，影响判断 | 单点强调色 + 图标 |
| 悬停才显示关键操作 | 触控板/键盘/读屏不可用 | 常驻主操作 + 右键/快捷键 |
| 用颜色作为唯一状态 | 色盲不可用 | 颜色 + 图标 + 文本 |
| 用动画阻塞操作 | 高频流程变慢 | 后台任务 + 可取消 + 即时反馈 |
| 仿游戏背包网格限制布局 | 桌面宽屏浪费、扫描困难 | 自适应卡片/表格 |

### 5.4 氛围等级

| 等级 | 内容 | 默认 |
|---|---|---|
| 关 | 纯专业深色工具；无扫描线/星点/HUD 角标 | 否 |
| 轻 | 深空调色、琥珀/青强调、等宽数据字体、3D 角标 | 是 |
| 沉浸 | 增加静态星点、低透明扫描线、Hero 动效（仍可关） | 否 |

**硬约束**：任何等级下，布局、焦点、对比度、快捷键、错误信息完全一致；切换等级不需要重启。

## 6. 桌面交互规范

### 6.1 焦点与 Tab

- 焦点环统一 2px 青色（`#5AD7FF`），与背景有 ≥3:1 对比；不仅靠颜色，可有 1px 外发光。
- Tab 顺序遵循视觉顺序：Rail → CommandBar → 页面主区 → Inspector → Dock。
- `F6` 在四个区域间循环；`Shift+F6` 反向。
- 对话框打开时焦点进入首个输入/主按钮；关闭后焦点回到触发控件。
- 不允许焦点进入隐藏/禁用/折叠控件；折叠面板用 `setFocusPolicy(Qt.NoFocus)`。
- 列表/表格支持方向键、Home/End、PageUp/PageDown；空格切换勾选；Enter 打开详情。
- 自定义 delegate 必须提供键盘焦点绘制；不能只有鼠标悬停态。

### 6.2 快捷键

| 范围 | 快捷键 | 动作 |
|---|---|---|
| 全局 | `Ctrl+K` | 命令面板 |
| 全局 | `Ctrl+1..6` | 切换一级页面 |
| 全局 | `Ctrl+F` | 聚焦当前页搜索/过滤 |
| 全局 | `F5` | 刷新当前页数据 |
| 全局 | `F1` / `Ctrl+/` | 快捷键速查 |
| 全局 | `F6` / `Shift+F6` | 区域循环 |
| 全局 | `Esc` | 关闭覆盖层/清空搜索/折叠 Inspector |
| 全局 | `Ctrl+Shift+J` | 展开/收起 JobDock |
| ShipLab | `Ctrl+Enter` | 开始搜索 |
| ShipLab | `W` / `E` / `C` / `F` | 写回 / 导出 / 复制种子 / 收藏 |
| ShipLab | `Delete` | 删除选中条件 chip |
| ShipLab | `Ctrl+A` / `Ctrl+Shift+A` | 全选结果 / 加入对比 |
| Fleet | `Ctrl+O` / `Ctrl+R` | 打开存档 / 重新读取 |
| Fleet | `Ctrl+Shift+E` | 导出选中 |
| Galaxy | `Ctrl+G` | 聚焦地址工作台 |
| Galaxy | `Ctrl+Shift+C` | 复制当前地址 |
| GameLink | `Ctrl+L` / `Ctrl+Shift+C` | 聚焦日志 / 复制日志 |
| Settings | `Ctrl+S` | 保存设置（显式） |

**规则**

- 单字母快捷键只在对应列表/面板有焦点时生效，避免与输入框冲突。
- 所有快捷键可在命令面板/速查表中看到；冲突时以全局为准，页面动作让位。
- 不使用游戏内全局热键抢占；未来若做 overlay，需用户显式开启。

### 6.3 右键菜单

- 每个对象都有上下文菜单，且与选择状态一致；空白处右键显示“刷新/全选/粘贴地址”等页面级动作。
- 键盘 `Menu` 键或 `Shift+F10` 打开；菜单项显示快捷键；危险项用分隔线隔离。
- 菜单项示例：
  - 飞船：预览 / 复制种子 / 加入对比 / 收藏 / 写回存档… / 导出 glb… / 在文件夹中显示
  - 行星/扫描结果：复制符文 / 复制坐标 / 复制系统信息 / 传送到此 / 置顶符文 / 加入对比
  - 任务：取消 / 复制错误 / 打开日志
  - 日志：复制 / 全选 / 清空 / 保存
  - 部件：设为想要 / 设为不要 / 清除
- 不可用项禁用并给出原因 tooltip；不要隐藏到用户找不到。

### 6.4 拖拽

- 条件 chip：拖拽排序；拖到托盘外可删除（需确认或可撤销）。
- 结果卡片：拖到对比托盘；拖出为纯文本种子/地址。
- `.hg` 文件：拖到 Fleet/Settings 路径区即读取；拖拽时高亮 drop zone。
- 地址/坐标文本：支持从剪贴板/浏览器拖入输入框。
- **禁止**拖拽直接触发写回/传送；破坏性动作必须经过确认面板。
- 拖拽中 `Esc` 取消；drop 失败给出原因；不支持拖拽的场景提供“上移/下移/添加”按钮作为键盘替代。

### 6.5 多选与批量操作

- 支持 `Ctrl+点击` 增减选择、`Shift+点击` 范围选择、`Ctrl+A` 全选；表格支持行选择。
- 多选后显示 `SelectionActionBar`：“已选 N 项” + 可用动作 + 清除选择。
- 批量动作仅限非破坏性：导出、收藏、复制种子/地址、加入对比；**写回/传送不做批量**。
- 批量确认显示数量、目标目录/格式、预计时间；执行中可取消；部分失败列出失败项并可重试。
- 选择状态在筛选/排序后尽量保持（用稳定 ID），但删除对象时清理失效选择。

### 6.6 错误恢复

统一错误信封（来自 `docs/ARCHITECTURE.md` 的方向）：

```text
{kind, message, hint, retryable, details, job_id}
```

- UI 只显示 `message + hint`，`details` 折叠/可复制；完整栈写日志。
- 可恢复错误用内联错误或 Toast，不用模态弹窗；模态只用于破坏性确认。
- 失败时**保留用户输入和已有结果**；不要清空搜索条件/列表。
- 每个错误必须有“下一步”：重试、去设置、打开日志、复制详情、降低条件。
- 轮询/自动刷新失败采用退避（1s → 2s → 5s → 10s），停止时显示“已暂停，手动刷新”。
- 写操作：备份 → 原子写 → 读回校验 → 失败回滚；UI 展示每一步与备份路径；成功后提示重载存档。
- 任务取消是正常状态，不显示为错误；取消后清理进度并恢复按钮。

### 6.7 可访问性

- 所有图标按钮设置 `accessibleName` / `accessibleDescription`；自定义绘制卡片通过 model 数据或 `QAccessible` 暴露文本。
- 读屏播报任务开始/完成/失败、页面切换、错误摘要；避免连续刷屏。
- 键盘可完成所有核心流程；拖拽必须有键盘替代。
- 对比度：正文 ≥4.5:1，大文本 ≥3:1；焦点环 ≥3:1；禁用态仍可辨。
- 状态用“颜色 + 图标 + 文本”三重表达；符文图片提供等价的 12 位文本。
- 尊重系统“减少动效”；提供高对比主题；字号可放大到 150% 不截断。
- 日志/表格支持复制；错误文本可选中；不把关键信息只放在 tooltip。
- 表单使用 `QLabel.setBuddy()` 或 `QFormLayout` 标签关联，读屏能读出字段名。

### 6.8 DPI 与窗口

- Windows 使用 Per-Monitor V2 DPI 感知（打包 manifest/Qt 属性）；Qt6 默认高 DPI，保留 `PassThrough` 舍入策略。
- 尺寸使用逻辑像素/布局管理器；避免固定 190px Rail、208px 卡片这类硬编码；必要处用 `QFontMetrics` 计算。
- 图标提供 SVG 或 @1x/@2x；优先 `QIcon` 多分辨率，不使用低清位图放大。
- 最小窗口 1024×720；1366×768 无横向滚动；1920/2560/4K 布局不空洞。
- 卡片网格按可用宽度动态列数；表格列宽可调、可记忆；长文本省略 + tooltip。
- Splitter 设置最小宽度，避免 Inspector 被拖到 0；屏幕变化时把窗口钳制到可见区域。
- 测试矩阵：100% / 125% / 150% / 200%；单屏 1366×768、1920×1080、2560×1440、4K；多显示器混合 DPI。
- 多显示器下 overlay/浮窗位置按当前屏幕计算，不使用主屏坐标硬编码。

### 6.9 反馈时延与性能预算

- 点击后 100ms 内必须有视觉反馈（按钮按下/加载态）。
- 超过 1 秒的操作显示 spinner/进度；超过 3 秒进入 JobDock 并可取消。
- UI 线程不做文件 IO、解包、搜索、3D 几何生成；沿用 worker + 信号。
- 列表滚动目标 60fps；缩略图只加载可见项；大结果集用 model/view。
- 空闲时不做持续动画；扫描线静态或极低频；减少动效时全部停止。
- 启动预算：Shell 可交互优先于数据加载；页面懒加载；失败不阻塞其他页面。

## 8. 不重复造轮子、不增加无谓依赖

### 8.1 优先复用 Qt 已有能力

| 需求 | 使用 | 不要自造 |
|---|---|---|
| 结果列表/表格 | `QAbstractListModel` / `QAbstractTableModel` + `QListView/QTableView` | 手写 item 池、自己实现虚拟滚动 |
| 搜索/排序 | `QSortFilterProxyModel` | 每次筛选重建全部 item |
| 设置/布局记忆 | `QSettings` | 自写 INI/JSON 配置层 |
| 路径 | `QStandardPaths` + 现有 `core/paths.py` | 重复拼 AppData 路径 |
| 右键菜单 | `QAction` + `QMenu` | 自绘菜单 |
| 撤销 | `QUndoStack` | 自写命令栈 |
| 动画 | `QPropertyAnimation` / QSS transition-like | 引入动画框架 |
| 可访问性 | `QAccessible` + `setAccessibleName` | 自造读屏协议 |
| 文件选择 | `QFileDialog` | 自写文件浏览器 |
| 3D | 现有 `QOpenGLWidget` / `ShipViewer` | 引入 WebGL/Three.js |
| 星图/属性条 | `QPainter` | 引入图表库 |
| 测试 | `PySide6.QtTest`（已有依赖） | 为 UI 测试新增运行时依赖 |

### 8.2 不新增的依赖

- 不引入第二套 UI 框架：PyQt、DearPyGui、qfluentwidgets、qdarktheme、superqt。
- 不引入 Web 外壳：Electron、Tauri、pywebview（旧外壳应继续降级/移除，而不是扩展）。
- 不引入数据处理大库：pandas、polars；当前数据量用 Python 标准库 + NumPy 足够。
- 不引入网络/云 SDK；更新检查与分享默认离线。
- 不引入第三方图标包/字体包；图标用内联 SVG/QPainter，字体用系统字体。
- 不引入 OCR/ML 依赖；游戏内数据优先走 agent/存档，不做截图识别。
- 不为“氛围”引入着色器框架/粒子库；3D 已有 OpenGL 管线，效果控制在现有能力内。

### 8.3 例外流程

若未来确实需要新依赖，必须满足：

1. 现有依赖无法在合理工作量内实现；
2. 许可证兼容（MIT/BSD/Apache 优先，GPL 需评估分发影响）；
3. 打包体积增加可接受（记录 before/after）；
4. 可选依赖 + 懒加载，缺失时功能降级而不是启动失败；
5. 在 `THIRD_PARTY_NOTICES.md` 记录；
6. 有明确的移除/替代方案。

## 9. 风险与开放问题

| 风险 | 说明 | 缓解 |
|---|---|---|
| 视觉改造拖慢功能 | NMS 氛围容易过度设计 | 先做阶段一的交互与状态；氛围层可关 |
| 模型迁移工作量大 | QListWidget → model/view 涉及选择/缩略图/委托 | 先 ShipLab 试点，再推广到 Fleet/Galaxy |
| 任务取消不彻底 | 搜索进程/线程可能不响应取消 | JobService 定义协作式取消；UI 先停止接收结果 |
| 写档安全 | 备份/回滚/版本差异 | 保持单对象写回；前置检查；失败自动回滚；不做批量 |
| 社区兼容 | 分享码/JSON 格式不统一 | 先做自有格式 + 导入预览；不承诺外部协议 |
| 可访问性成本 | 自定义 delegate 需要额外工作 | 优先给列表提供等价文本视图/accessibleName |
| DPI 回归 | 固定像素遍布现有代码 | 阶段一先替换 Rail/卡片固定尺寸；阶段二全面清理 |
| 许可证 | 参考项目可能 GPL | 只借鉴交互，不复制代码；新增依赖走例外流程 |

**开放问题**

1. NMS 氛围默认等级：默认“轻”还是“关”？建议默认“轻”，并提供一键关闭。
2. 是否保留 `Ctrl+1..6` 与单字母快捷键的冲突策略？建议单字母仅在列表聚焦时生效。
3. 是否需要“平板/触控”支持？当前定位桌面键鼠，暂不为触控重排布局。
4. 分享码是否要兼容社区格式？建议先做内部格式，社区导入作为阶段三。
5. 多语言是否纳入阶段三？建议先集中字符串，不急于翻译。
