# agent 是什么，为什么传送/扫描必须用它

> 面向使用者/测试者，不是协议文档。协议细节见 `docs/AGENT-PROTOCOL.md`。

---

## 1. 一句话

**agent 是一段只在本机运行的小型 Python Mod，由 pymhf 注入 `NMS.exe` 进程，替 starforge 调用游戏自己的函数。**

它不是外挂服务器、不联网、不上传数据；它只是把“starforge 想做的游戏内操作”翻译成游戏进程内真正的函数调用。
当前实现使用 **pymhf + NMSpy**（MIT 开源）：NMSpy 负责结构体/函数签名，pymhf 负责注入和 HTTP API。

---

## 2. 不用 agent 行不行？

| 做法 | 能做什么 | 做不了什么 |
|---|---|---|
| **改存档**（现在的 starforge） | 换船种子、改船级/属性、读船/同伴 | 游戏运行中的即时操作；传送后不重载 |
| **外部读内存**（Super Ship Hunter 路线） | 找到模板槽、写 8 字节种子、读一些状态 | 调用游戏 C++ 函数；可靠传送；扫描；建造 |
| **agent（进程内 DLL）** | 调用游戏函数、读写对象、传送、扫描、建造 | 需要按游戏 build 校准；有崩溃/杀软风险 |

**关键区别**：内存是“数据”，函数是“行为”。
传送要改玩家位置/星系并让游戏刷新，扫描要调用游戏的扫描/发现逻辑，建造要进入游戏的建造状态——这些不是改几个字节就能稳定做到的，必须**在进程内调用函数**。

## 3. 它是怎么工作的

```
starforge.exe（Python/Qt）
        │  http://127.0.0.1:5000/StarforgeAgent
        │  JSON（GET/PUT）
        ▼
starforge_agent.py（pymhf Mod，在 NMS.exe 进程内）
        │  1. 用 NMSpy 的结构体偏移/函数签名
        │  2. 读写 GcPlayerState / GcSolarSystem / 船槽
        │  3. 写位置后触发 APPLOCALLOAD
        │  4. 写前快照，失败 restore
        ▼
NMS.exe（单人游戏）
```

安装/启动方式（应用内按钮完成，不需要命令行）：
1. 点「安装/更新游戏内组件」→ 安装与当前 build 匹配的 NMSpy + pymhf；
2. 点「安装 Mod」→ 写入 `~/.starforge/agent/starforge_agent.py`；
3. 进游戏存档，点「注入并连接」→ pymhf 把 Mod 注入正在运行的 `NMS.exe`；
4. 卸载：删除 Mod 文件/停止注入即可；不改游戏 pak。

> 这是运行时注入（pymhf），不是 PCBANKS Mod。仅单人模式；有杀软误报可能，默认不安装。

## 4. agent 能提供哪些能力

按风险从低到高：

| 能力 | 说明 | 风险 |
|---|---|---|
| `hello` | 握手、报告 NMSpy 版本和可用能力 | 无 |
| `player` | 当前 UA、坐标、位置、星系名 | 只读 |
| `system` | 当前星系 + 行星表 | 只读 |
| `planet` | 当前行星天气/资源/动植物/哨兵 | 只读 |
| `ships` | 游戏内 12 个船槽的模型/种子 | 只读 |
| `teleport` | 写位置并触发 `APPLOCALLOAD`（写前快照） | 高 |
| `restore` | 还原上一次传送 | 中 |
| `scan` | 读取行星扫描字段；`discover` 暂未开放 | 中 |
| `build.anywhere` / `recolour` / `limit.unlock` | 后续阶段 | 高 |

starforge 只会放行白名单命令；未知命令在 Python 侧直接拒绝，不发到 DLL。

## 5. 为什么必须按游戏 build 绑定

NMS 每次更新都可能：
- 改变函数地址；
- 改变结构体字段偏移；
- 改变虚表顺序；
- 改变数据表常量。

所以 agent 不硬编码“第 123456 字节”，而是：
1. 用 `NMS.exe` 的 **sha256 + size + version** 算出 build id；
2. 在地址书里找这个 build 的签名/偏移；
3. 找不到 → **只读或拒绝**；
4. 找到多个同样可信的候选 → **拒绝写入**，让你回报。

你的机器已经记录了一份 build：

```
version 185034
size    89,540,680
sha256  092236962EE050E419424699B5C343A0173F7773D5AD0866B7EC366D334C07D4
```

- 地址书：`starforge/live/builds/185034.json`（当前 `unverified`，用于诊断/回退）；
- **实际结构体偏移/签名由 NMSpy 提供**。NMSpy 每个游戏 build 发一个版本（本机对应 `NMSpy==185034.0`），应用会自动选择并安装匹配版本；游戏更新后点一次「安装/更新游戏内组件」即可。

## 6. 安全边界

- **只支持单人**：检测到其他玩家在线时，传送/建造/扫描奖励全部禁用。
- **写前快照**：agent 先记录原值，失败自动 `restore`。
- **写后校验**：读回确认，不一致就回滚并报错。
- **默认关闭**：不安装 agent 时，所有游戏内写能力不可用。
- **不联网**：命名管道只在本机；不上传存档/账号/日志。
- **可卸载**：完整还原 `winmm.dll`。
- **不做**：多人写入、在线反作弊规避、刷资源/挂机。

---

## 7. 为什么不能只用外部内存做传送

外部程序可以 `ReadProcessMemory/WriteProcessMemory`，但：
- 不知道对象生命周期，写完游戏可能立刻覆盖；
- 传送不只是改坐标，还要让星系/行星/飞船状态刷新；
- 扫描要调用游戏函数并处理返回值；
- 建造要进入游戏的建造模式、校验资源/权限/碰撞。

这些都需要**在进程内执行代码**，所以 agent 是可靠方案；外部内存只适合“模板槽写入”这类简单数据。

---

## 8. 对测试者的实际影响

- 不装 agent：搜船、3D、存档编辑、种子反查、银河索引、符文浮窗全部可用。
- 装 agent：先跑只读 `agent hello`，确认当前 build 命中；再逐项开启传送/扫描。
- 每次游戏更新：如果 build 变了，agent 会显示“这版未验证”，不会硬写。
- 出问题：设置页「游戏内」会显示能力表和原因；把 `agent hello` 的 JSON 整段贴回即可定位。
