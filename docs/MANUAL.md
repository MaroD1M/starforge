# Starforge 用户手册

> 适用版本：**0.15.0**（`starforge/__init__.py:17`）。  
> 本手册按**当前代码实际行为**编写：界面文字、按钮、快捷键、默认值和限制均取自源码；凡未实机验证的能力会明确标注“实验性/未验证”。  
> 这是一款**原生 Qt（PySide6）桌面程序**，默认入口不是网页。

---

## 0. 一分钟了解

### 0.1 一句话定位

**Starforge 是《无人深空》的本地飞船与星球情报台**：按部件/涂装搜索飞船种子，用你自己游戏里的模型看真 3D，查星系与传送门符文，并在“默认只读、写入前备份”的保护下，把结果写回存档或送进游戏里的模板槽。

### 0.2 能做什么

| 你想做的事 | 在哪里做 | 游戏状态要求 | 说明 |
|---|---|---|---|
| 按部件/涂装搜飞船种子 | 飞船实验室 | 不需要运行 | 只在**同一船型内**搜索；8 种可搜索船型；可设预算与线程 |
| 看真 3D、旋转缩放 | 实验室 / 设计器 | 不需要运行，但需要游戏目录里的 pak | 读你自己的游戏资源；没有游戏目录时退回服务端渲染图 |
| 导出 glb、截图、渲染图 | 飞船实验室 | 需要能生成真 3D（L1） | glb 写到缓存目录；截图可另存 |
| 收藏、分享码 | 飞船实验室 | 不需要 | 分享码以 `nsh1:` 开头 |
| 读存档里的飞船、同伴、护卫舰、工具、货船 | 我的船队 | 不需要运行 | 后三类与同伴是**只读** |
| 同型换种子写回 | 实验室“写入存档” + 船队定位槽位 | **必须先退出游戏** | 备份 → 原子写 → 读回 → 失败回滚；可只写副本 |
| 改船级/属性 | 我的船队 → 船级/属性… | **必须先退出游戏** | C/B/A/S；可按等级取“最佳属性”；越界值会被拒绝 |
| 改货币、飞船名称、涂装 | 我的船队 → 存档编辑… | **必须先退出游戏** | 单位/纳米/水银；名称最多 64 字符；颜色按游戏调色板取最近色 |
| 改库存、词语/知识、任务、奖励 | 我的船队 → 扩展编辑… | **必须先退出游戏** | 只调用上游已验证字段；同样有备份/读回/回滚 |
| 星图、行星表、本星系船池、银河索引 | 星图 | 不需要运行，但需要游戏目录 + unicorn | 扫描结果写入本地索引，不写游戏 |
| 解析 12 位符文串、按种子反查星系 | 星图 → 地址工作台 | 不需要运行 | 坐标文本**不支持**直接解析；反查可能“欠定” |
| 传送门符文置顶浮窗 | 星图详情 / `glyph-overlay` 命令 | 不需要运行 | 独立置顶窗口，不注入游戏 |
| 模板 Mod 一键安装 | 游戏内代理 → “安装模板 Mod” | 不需要游戏运行，但必须已配置游戏目录 | 写到 `<游戏目录>/GAMEDATA/MODS/starforge-templates`；装完重启游戏 |
| 模板槽“送进游戏” + 游戏表情菜单领取 | 实验室/船队选中飞船 → “送进游戏” | **游戏必须运行并已进入存档** | 只改内存里的 **8 字节种子**，不碰存档；需要先装模板 Mod |
| 实时资产（多功能工具/货船/同伴） | 游戏内代理 → “实时资产” | 游戏运行且 agent 已连接并进入存档 | 只读；走 agent 的 `/multitool`、`/freighter`、`/pets` |
| 传送到星球（传送门机制） | 星图 → “传送到此星球”；或游戏内页“传送门效果” | 游戏运行且 agent 已连接；**非多人** | 默认 `prepare_warp`；未验证 build 需显式打开 `allow_unverified_agent`；见 3.7 |
| 游戏内实时遥测、行星档案、扫描 | 游戏内代理 | 游戏运行且注入成功 | **实验性**；当前版本默认不可依赖，见第 4 节 |

### 0.3 明确不做

- **不做跨型移植外观**：`seed` 与船型绑定，同一 `seed` 在另一种船型上会长成完全不同的船。写回只允许同型。
- **不让固定模型船改外观**：非 `_PROC` 船的种子不决定外观；程序会拒绝并提示。
- **不伪造游戏里不存在的数值/物品**：船级属性必须落在游戏允许区间内；货船、护卫舰、多用途工具只读；同伴 3D 需要生物生成器，目前不提供。
- **不做多人联机同步/多人专用写入**：存档写入只改你选择的本地文件；代理检测到多人模式时会禁用高风险写。
- **不把“一键传送”当稳定功能**：传送依赖实验性的游戏内代理；未验证 build 默认被 build 闸门拦住，只有显式打开 `allow_unverified_agent` 才放行实验写。
- **不提供离线星球生物扫描/生物模型**：这些需要游戏内通道或生物生成器。
- **模板 Mod 可以一键安装，但不会自动启用**：装完必须重启游戏；卸载就是删 `<游戏目录>/GAMEDATA/MODS/starforge-templates`（见 3.6）。
- **不保证模板种子跨重启**：改的是游戏进程内存，重启游戏后模板槽会回到 Mod 里的出厂种子。
- **不修改游戏代码、不注入 DLL**：游戏内代理是 pymhf + NMSpy 的 Python Mod；特定注入场景（如每帧补绑、进程被 Steam 接管）会让游戏以“模组冲突”退出，但不是所有注入都会触发。

### 0.4 名词

| 名词 | 含义 |
|---|---|
| 种子 / Seed | 64 位整数，通常写成 `0x…` 十六进制；决定程序化飞船的外观 |
| 船型 / type | 战斗机、运输舰、拦截机等；写回时必须同型 |
| 程序化船 / `_PROC` | 外观由种子决定的船；固定模型船不受种子影响 |
| UA / 银河地址 | 星系/行星的 64 位地址，含星系、行星、坐标等位段 |
| 符文串 / glyphs | 传送门用的 12 位十六进制字符；**不是** UA 直接截 12 位，需按位段重排 |
| 模板槽 | 模板 Mod 提供的 8 个奖励槽，每个对应一种船型；Starforge 只改其中的种子字段 |
| L0 / L1 | L0 是服务端渲染图；L1 是从游戏 pak 解出的真 3D |
| 副本 `.edited.hg` | 勾选“写入副本”后生成的文件，原存档不动 |
| 游戏内代理 / agent | pymhf + NMSpy 的 Python Mod，用于读取/写入游戏运行时状态；实验性 |

## 1. 安装与启动

### 1.1 发布包（Windows，推荐）

1. 从 Release 下载 `starforge-*-win64.zip`。
2. **解压到一个可写目录**（不要放在 `Program Files` 下，也不要覆盖旧版本目录）。目录里应同时存在：
   - `starforge.exe`：无控制台启动器；
   - `starforge-cli.exe`：真正的命令行/内核；
   - `_internal\`：依赖与资源。
3. 双击 `starforge.exe` 打开原生窗口；再次双击会把已有窗口拉到前台，不会开第二个主窗口。
4. 命令行用法：

```bat
starforge.exe doctor
```

`starforge.exe` 会把参数转发给同目录的 `starforge-cli.exe`；如果终端没有输出，直接运行：

```bat
starforge-cli.exe doctor
```

发布包**不需要安装 Python**。桌面界面、实时内存通道和游戏内代理目前面向 Windows；源码模式下的存档读写/CLI 可在其它平台使用，但原生界面需要自行安装 PySide6。

> 升级时请解压到**全新目录**再替换，不要直接覆盖旧目录。程序用 NumPy 等原生 DLL；被旧文件/杀软拦截时，启动会弹“NumPy 不可用”的提示（`starforge/app/main.py:116`）。

### 1.2 源码运行

要求 Python 3.10+（`pyproject.toml:5`）。

```bat
git clone <仓库地址>
cd starforge
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 告诉它上游算法库仓库（源码模式必需）
set STARFORGE_SHIPWRIGHT=<Shipwright 仓库>

# 可选：如果你有 Gagarin 的 GAMEDATA（含 Gagarin/ships/catalog.txt）
set STARFORGE_GAMEDATA=<GAGARIN GAMEDATA>

python -m starforge selftest
python -m starforge app
```

也可以 `pip install -e .` 后直接使用 `starforge` 命令（`pyproject.toml:13`）。

源码模式与发布包的区别：

- 发布包内置了 NMS-Shipwright 的运行时代码（`nms_save` / `nms_procgen`），所以不需要另装；源码模式需要 `STARFORGE_SHIPWRIGHT` 或同机仓库。
- 发布包**不包含 Gagarin 的 `catalog.txt`/`icons.bin`**。没有它也能用：部件树优先从游戏 pak 推导（`starforge/parts.py:57`）。
- `requirements.txt` 里的 PySide6 只在 Windows 安装；Linux 源码模式要自己装 PySide6 才有原生窗口。

### 1.3 首次启动：路径是怎么被找到的

Starforge 有三类路径，行为并不一样：

| 路径 | 首次启动会不会自动填 | 解析规则 |
|---|---|---|
| 存档目录 | **读取存档时会自动解析**，但不一定写进设置 | 设置里的 `saves_dir` → `STARFORGE_SAVES` → `%APPDATA%\HelloGames\NMS\st_*\` 中含 `*.hg` 的目录（`starforge/core/settings.py:100`） |
| 游戏目录 | **不会在启动时自动写入设置** | 需要点“设置 → 自动检测”，或设置 `NMS_DIR`，或手动选择游戏根目录（`starforge/core/settings.py:156`） |
| 数据目录（Gagarin GAMEDATA） | 不强制 | 显式 `gamedata_dir` 必须含 `Gagarin/ships/catalog.txt`；否则回退自动发现/环境变量；发布包通常没有它，部件从游戏 pak 推导 |

**第一次使用的正确顺序：**

1. 打开“设置”。
2. 点“自动检测”。它会尝试：`NMS_DIR` → NMS-Shipwright 的 Steam/GOG/注册表查找 → 自己扫 Steam 库。
3. 如果没找到，点“游戏目录”的“浏览…”，选择**游戏根目录**——必须同时含 `Binaries\NMS.exe` 和 `GAMEDATA\PCBANKS`（`starforge/locate_game.py:26`）。
4. 存档目录通常会自动找到；找不到就“浏览…”选择含 `save.hg` 的目录。
5. 回到“概览”，确认四张状态卡：
   - 数据层：就绪；
   - 存档：已发现；
   - 游戏：已设置；
   - 写入：只读（默认）。
6. 如果“数据层”是“缺失”，通常是游戏目录没设置，且没有 Gagarin 数据；此时搜索/3D 都不可用。

> “概览”的 `F5` 只刷新这四张状态卡，不会重新加载当前页面的数据；页面里的“刷新”按钮才会重新读取。

### 1.4 应用数据放在哪

默认 `STARFORGE_HOME` 为 `%USERPROFILE%\.starforge`，可整目录删除来重置设置/缓存/历史。

| 路径 | 内容 |
|---|---|
| `~/.starforge/settings.json` | 设置 |
| `~/.starforge/history.json` | 最近活动（最多 200 条，首页显示 8 条） |
| `~/.starforge/favorites.json` | 收藏与分享码 |
| `~/.starforge/logs/starforge.log` | 主日志（2 MB 滚动，保留 3 份） |
| `~/.starforge/logs/faulthandler.log` | 原生崩溃栈 |
| `~/.starforge/cache/galaxy.db` | 银河索引（SQLite） |
| `~/.starforge/cache/gamecache/` | 上游解包缓存 |
| `~/.starforge/agent/` | 游戏内代理文件、运行时、`launcher.log`、token、传送快照 |
| `~/.starforge/builds/*.json` | 用户实测的游戏 build 指纹 |
| `~/.starforge/native-window.ini` | 窗口位置/大小 |

存档备份**不在** `~/.starforge`，而是写在存档同目录（见第 6 节）。

## 2. 界面导览

### 2.1 窗口结构

主窗口由四部分组成（`starforge/app/shell.py:93`）：

- **左侧导航栏**：七个页面，分组为“探索 / 资料 / 连接”；
- **顶部命令栏**：当前页面、命令面板按钮、四个状态芯片（数据层 / 存档 / 游戏 / 写入）、后台任务进度；
- **中间工作区**：当前页面；
- **底部任务栏**：进行中/已结束任务，可取消或隐藏。

状态芯片的含义：

- **数据层 ✓/✗**：能否取到部件表；
- **存档 ✓/✗**：是否解析到可读存档目录；
- **游戏 ✓/未设置**：是否配置了游戏目录；
- **写入已开/只读**：是否允许写存档；
- 右下角会显示“预览级别 L0/L1 · 原生窗口”。

### 2.2 七个页面

| 导航 | 页面标题 | 快捷键 | 主要用途 |
|---|---|---|---|
| 概览 | 今日战报 | `Ctrl+1` | 状态总览、快速入口、最近活动 |
| 飞船实验室 | 飞船实验室 | `Ctrl+2` | 条件搜索 → 结果 → 3D 检查器 → 写回/送进游戏 |
| 我的船队 | 我的船队 | `Ctrl+3` | 读存档、查看船队/同伴/护卫舰/工具/货船、改级、备份 |
| 星图 | 星图 | `Ctrl+4` | 当前星系、行星、船池、扫描、银河索引、地址工作台 |
| 游戏内代理 | 游戏内代理 | `Ctrl+5` | 连接游戏、实时遥测、行星档案、传送/扫描（实验性） |
| 设置 | 设置与诊断 | `Ctrl+6` | 路径、写入开关、备份数、线程、体检、诊断包 |
| 设计器 | 飞船设计器 | `Ctrl+7` | 逐组选部件、即时 3D、搜索种子、写入存档 |

> **快捷键有一个容易记错的点**：设计器是 `Ctrl+7`，`Ctrl+3` 是“我的船队”。源码里为了让新页面不打乱既有编号，把设计器排到了最后（`starforge/app/shell.py:47`）。

#### 概览

- 四张状态卡：数据层、存档、游戏、游戏内代理；点击卡片会跳到相关页面。
- “快速开始”：开始找船、设计器、我的船队、地址工作台、收藏夹、星图、连接游戏。
- “最近活动”：最近 8 条搜索/写回/备份/扫描/代理操作；点击可跳转；“清空历史”只清本机记录。
- “最近状态”和“第一次使用”提示。
- 右上角“刷新状态”等同于 `F5`。

#### 飞船实验室

三栏布局：条件 → 结果 → 详情。

**左栏（条件）**

- 船型下拉：拦截机/战斗机/运输舰/探索舰/穿梭机/异星/生物舰/太阳帆。
- 模式：**想要** / **不要**；勾选部件即加入当前模式。
- 部件名筛选框；部件树带图标和悬停预览；当前部件可点“3D”开独立小窗。
- 已选条件摘要；点击摘要可清空条件。
- 涂装筛选：勾选“按涂装筛”，选主色；可再勾“副色也接近”，容差 0.10/0.18/0.28/0.40（默认 0.18）。
- 搜索预算：1–2000（百万种子），默认 200；越大越慢，但更容易命中稀有组合。
- 并行线程：发布包默认且最大为 1；源码模式默认 4，界面最多可选 8（受 CPU 核数限制，`starforge/app/pages/ship_lab.py:39`）。
- “开始搜索 / 取消 / 示例”；下方显示估算、已测种子数与速率。

**中栏（结果）**

- 网格/列表切换；结果最多 24 个；搜索时间上限 180 秒。
- 多选 1–3 艘加入对比；对比弹窗可并排看缩略图、属性、部件。
- “清空结果 / 重置条件”。
- 双击结果卡片会复制种子。

**右栏（详情）**

- 3D 视口：拖动旋转、滚轮缩放、双击复位；等轴/俯视/侧视/正视、自转、截图。
- “复制种子 / 收藏 / 分享码 / 渲染图”（渲染图是服务端兜底图）。
- “查星系”：按种子反查可能来自的星系；候选需生成器证实，可能欠定。
- “导出 glb”：只能在该船能生成 L1 真 3D 时成功。
- “写入存档”：打开写回对话框（同型槽位）。
- “送进游戏”：把当前种子写进模板槽（见 3.6）。
- “导入分享”：粘贴 `nsh1:` 分享码。

页面内快捷键：`Ctrl+Return` 开始搜索、`Ctrl+F` 聚焦筛选、`Esc` 清除结果选择、结果列表内 `J/K` 上下移动。

#### 设计器

- 左栏“船型与部件”：每组**单选**一个部件；“清空”清除所有组。
- 中栏“3D 预览”：选部件后即时生成；等轴/俯视/侧视/正视、自转。
- 右栏“已选部件”摘要、预览种子输入框、“复制种子”。
- “用这些部件搜索种子”：固定预算 20M、20 秒、最多 12 个结果、1 线程（`starforge/app/pages/ship_designer.py:843`）。
- 搜索并选中种子后，可“写入存档…”：新建飞船（第一个空槽）或替换现有槽；可同时涂装；默认勾选写入副本。
- “保存设计…/载入设计…”：本地 `.nmsdesign.json`，**不写存档**。

#### 我的船队

顶部按钮：读取存档、备份恢复、存档编辑…、扩展编辑…、批量导出。

- 存档路径可手填或“浏览…”；读取后监视文件变化，外部存档变化会自动刷新（编辑弹窗期间除外）。
- 五个标签页：**飞船 / 同伴 / 护卫舰 / 工具 / 货船**。
  - 飞船：可选中、看 3D、复制种子、改船级/属性、送进游戏；
  - 同伴：只读描述符与种子，不伪造 3D；
  - 护卫舰/工具/货船：只读表格，不提供写回。
- 飞船列表支持按类型/等级/种子排序，卡片/列表视图。
- “批量导出”：把**当前存档里的所有飞船**导出为 ZIP（glb + png + `manifest.json`）；固定模型船只写清单、不导出 3D。
- “备份恢复”：列出当前存档的备份，二次确认后恢复；恢复前会自动留一份当前快照。
- “存档编辑…”：货币、飞船名称/涂装；默认写副本。
- “扩展编辑…”：库存、知识/词语、任务、奖励；默认写副本。

#### 星图

- 顶部：刷新、扫描、取消扫描、导出 CSV。
- “当前星系”卡：星系名、符文串、坐标、种族、行星数、异常状态；可复制符文。
- 筛选条：群系、哨兵、种族、拦截机、最少行星、异常状态、扫描系统数（20–767，默认 200）。
- 标签页：**行星 / 本星系船池 / 扫描结果 / 银河索引 / 地址工作台**。
  - 行星：当前星系的行星列表；
  - 本星系船池：类型/类别/种子/来源；
  - 扫描结果：按条件扫描附近星系，结果写入本地银河索引；取消会在当前系统完成后停止；
  - 银河索引：按群系/哨兵/种族/异常/行星数/拦截机查询，最多 500 行；可导出 CSV；
  - 地址工作台：解析 12 位符文串，或按 `0x…` 种子反查星系。
- 右侧详情：复制符文串/坐标、**浮窗显示符文**、**定位并填入传送**（只填游戏内页的输入框，不写游戏）。

#### 游戏内代理

- “连接状态”卡：三步芯片（1 运行时 / 2 游戏内组件 / 3 游戏内代理）、游戏版本、多人状态。
- 按钮：连接游戏、启动游戏并注入、停止注入器、刷新状态、修复运行时/游戏内组件、**外部内存只读探测**、**安装模板 Mod**、打开 Mods 目录。
- “实时遥测”：玩家位置、当前星系、当前行星、游戏内船槽。
- “实时资产”：多功能工具（6 槽 + 当前槽）、货船与舰队（含护卫舰）、同伴（30 槽）；均为**只读**，连接成功并进入存档后自动拉取。
- “行星档案”：读取当前行星天气、哨兵、资源、动植物与生物 ID；可刷新/复制。
- “安全区”：符文地址、传送方式（普通写位置/传送门效果）、目标星系、传送到此地址、还原上一次传送、读取当前行星扫描、游戏内扫描即时完成、“允许未验证游戏版本实验写操作”。
- “附近兴趣点”：传送门/古遗迹/货船/飞船；当前未校准，按钮可能不可用，**不会伪造坐标**。
- “日志”：JSON 原样记录，可复制/清空。

#### 设置

- 路径：游戏目录、存档目录；各有“浏览…”，以及“自动检测 / 保存”。
- 安全与性能：允许写入存档、写入前二次确认、备份保留数、搜索线程数。
- 版本与代理：游戏 build、代理状态；刷新状态、复制最近日志、查看 `launcher.log` 摘要。
- 诊断：运行体检、导出诊断包、打开日志目录；下方是结构化文本输出。
- 关于：版本与“只监听本机、不联网、默认只读、代理默认不安装”的说明。

## 3. 典型工作流

### 3.1 按部件/涂装搜索飞船 → 看 3D → 导出

1. 确认“设置”里游戏目录已设置，且“概览”的数据层为“就绪”。
2. 打开“飞船实验室”（`Ctrl+2`）。
3. 选船型，例如“拦截机”。
4. 模式保持“想要”，在左侧部件树里勾选你要的部件；每组可以只勾一个，也可以勾多个。
   - 想排除某些部件：把模式切到“不要”再勾。
   - 用筛选框输入 `PIT`、`WING` 等快速定位。
5. 需要按颜色找：勾“按涂装筛”，点“主色”选颜色；需要副色时勾“副色也接近”并选容差。
6. 设定“搜索预算”（默认 200 百万）和线程数（发布包只有 1）。
7. 点“开始搜索”。状态栏会显示已测种子数和百万/秒；可随时“取消”。
8. 结果出来后选中一艘：
   - 右侧会生成 3D；拖动旋转、滚轮缩放、双击复位；
   - 可用“等轴/俯视/侧视/正视”和“自转”；
   - 3D 不可用时会自动退回服务端渲染图，并说明原因。
9. 需要留档：
   - “截图”保存当前视口 PNG；
   - “渲染图”看服务端渲染；
   - “导出 glb”生成模型文件；路径会显示在状态栏/提示里（缓存目录）。**只有 L1 真 3D 能导出 glb**。
10. 需要分享/复用：
    - “复制种子”；
    - “收藏”；
    - “分享码”复制 `nsh1:`；
    - 对方用“导入分享”粘贴。

补充：

- 搜索是**同型内**的；换船型要重新搜。
- 结果上限 24 个，搜索时间上限 180 秒；预算越大越慢。
- “没有命中”通常说明条件太严：减少“不要”条件、放宽涂装容差、提高预算。

### 3.2 我的船队：读存档、换种子、改船级/属性

#### A. 读存档

1. 打开“我的船队”（`Ctrl+3`）。
2. 首次进入会自动找默认存档（优先 `save.hg`、`save2.hg`）；找不到就点“浏览…”选择 `save.hg`。
3. 点“读取存档”。
4. 顶部会显示存档路径、飞船数量与警告。注意：
   - `accountdata.hg` 是账号数据，不是玩家存档；
   - `mf_*.hg` 是清单文件，不含飞船数据；
   - 固定模型船会提示“改种子无效”。
5. 飞船列表可以按类型/等级/种子排序；选中后右侧显示 3D、等级、属性与种子。
6. 存档被游戏或其它工具改动时，页面会自动刷新（编辑弹窗期间不刷新）。

#### B. 改船级/属性

1. **先完全退出游戏**。写入前检测到 `NMS.exe` 会拒绝（`starforge/save/writer.py:128`）。
2. 设置 → 勾选“允许写入存档”。
3. 船队里选中一艘飞船 → “船级/属性…”。
4. 选择新等级（保持不变 / C / B / A / S）。
5. 可勾“最佳属性”：按当前/新等级取各属性上限；此时下面手填的属性不会提交。
6. 不勾“最佳属性”时，只提交你改动过的属性；游戏不会给出越界数值，越界会被拒绝。
7. “写入副本”默认勾选：写 `save.edited.hg`，原档不动。确认无误后再把副本改名成 `save.hg`/`save2.hg` 进游戏验证。
8. 点“写入存档”，二次确认。
9. 成功后会显示备份路径；写后校验会确认：
   - 目标槽位等级正确；
   - **其它船的种子一个都没动**（防写错槽位）。

#### C. 换种子写回（同型）

> 船队页本身**没有**“换种子”按钮；换种子在“飞船实验室”的“写入存档”，或“设计器”的“写入存档”里完成。船队页用来确认目标槽位和改级。

推荐流程：

1. 完全退出游戏。
2. 设置 → 允许写入。
3. 船队 → 读取存档 → 选中目标船，记下槽位/船型。
4. 实验室 → 选**同船型** → 搜到/选中源船。
5. 点“写入存档”：
   - 选择存档（默认当前默认存档）；
   - “加载目标”；
   - 表格只列出**与源船同型且程序化**的槽位；
   - 选中目标槽；
   - 可勾“写入副本（save.edited.hg），不动原档”；
   - “确认写回” → 二次确认。
6. 成功后会显示备份路径与读回种子。

限制与保护：

- **跨型拒绝**：目标槽位船型与源不同会直接报错，并提示“同一个 seed 会长成完全不同的船”。
- **固定模型拒绝**：源船不是 `_PROC` 时，改种子不会改变外观，会报错。
- **写前备份、原子写、写后重新解码校验**；任何一步失败都会把原始字节写回（`starforge/save/writer.py:166`）。
- 写入期间游戏必须关闭；检测是“尽力而为”，检测不到时不会阻止，所以请自己确认游戏已退出。

#### D. 改货币、飞船名称、涂装

1. 退出游戏，开启写入。
2. 船队 → “存档编辑…”。
3. “货币”页：单位/纳米/水银；非负整数，上限 `2,147,483,647`；只提交改动过的币种。
4. “飞船”页：选目标飞船，改名称（最多 64 字符），或选主色/副色。
   - 颜色会按游戏调色板取最近色；
   - 只改名不会提交涂装。
5. “写入副本”默认勾选。
6. “写入存档” → 二次确认；成功/失败都会给出备份路径或可读错误。

#### E. 扩展编辑（库存、知识、任务、奖励）

船队 → “扩展编辑…”，四个标签页：

- **库存**：选择库存（玩家/飞船/货船/多用途工具/基地箱子等），可执行“填入选中格、改数量、清空选中格、填满堆叠、科技充满、修复损坏、扩满槽位”。
- **知识**：按种族“学会这些词语”；按分组（tech/products/base/customisation/refiner/cooking）“学会整组”。
- **任务**：列表刷新，勾选后“标记选中为完成”。
- **奖励**：分组（expedition/twitch/special/shop），可“解锁选中、锁定选中、标记已领取、设为可再领”。

这些写操作同样经过 `transact_save`：写开关、游戏进程检查、备份、原子写、读回校验、失败回滚（`starforge/save/extras.py:8`）。没有上游 API 的货船/护卫舰/中队写回不会伪造。

#### F. 批量导出

船队 → “批量导出”：

- 导出**当前存档里的所有飞船**，不是只导出选中项；
- ZIP 内含每艘船的 `.glb`、`.png` 和 `manifest.json`；
- 固定模型船只写清单并注明“外观不由种子决定”，不导出 3D；
- 失败项会记录在 `manifest.json`，状态栏会显示成功/失败数量。

#### G. 备份、恢复与回滚

- 每次写入前都会在同目录生成 `save.hg.<时间戳>.bak`（`starforge/save/writer.py:98`）。
- 默认 `backup_keep=0`：**永不自动删除备份**。
- 失败自动回滚：把写入前的原始字节原子写回；备份保留。
- 手动恢复：船队 → “备份恢复” → 选备份 → “恢复所选” → 二次确认。
  - 恢复前会再留一份当前状态快照；
  - 只接受文件名以当前存档名开头的备份，防止覆盖错文件；
  - 恢复也是一次写操作，需要开启写入并退出游戏。
- 极端情况（写一半断电）可能留下 `.part` 文件；原档在 `os.replace` 前不会被替换，若已替换但校验未完成，请用备份恢复。

### 3.3 设计器：选部件 → 预览 → 写入

1. 打开“设计器”（`Ctrl+7`）。
2. 选船型。
3. 在每个组里**单选**一个部件；右侧摘要会更新，3D 即时刷新。
   - 不选也可以预览默认外形，但“用这些部件搜索种子”至少需要一个部件。
4. 输入/粘贴“预览种子”，或直接用默认种子看效果。
5. 点“用这些部件搜索种子”：
   - 固定预算 20M、20 秒、1 线程、最多 12 个结果；
   - 结果里选中一个种子。
6. 点“写入存档…”：
   - 目标：新建飞船（第一个空槽）或替换现有槽；
   - 名称：留空使用船型名；
   - 可勾“同时涂装”，选主色/副色和调色板（FREIGHTER 含纯黑；SHIP 没有纯黑）；
   - “写入副本”默认勾选；
   - 确认写入 → 二次确认。
7. 写入成功后，写后校验会核对船型、种子、名称和涂装调色板；不一致会回滚。

注意：

- **替换槽位**时，如果目标槽原本是另一种船型，设计器会把整艘船换成目标船型（`set_ship_model`），这不是“把外观套到原船”。
- 新建飞船会克隆主船再换模型/种子；存档没有空槽时会提示先腾出槽位。
- 设计文件只存在本地 `.nmsdesign.json`，不写存档。

### 3.4 星图：星系/行星扫描与导出

1. 打开“星图”（`Ctrl+4`）。
2. 页面会先读“当前星系”。如果没有存档/游戏目录，当前星系会为空并给出提示。
3. 行星表/本星系船池会显示在标签页里；选中行星可在右侧看群系、哨兵、资源、坐标、符文串。
4. 扫描附近星系：
   - 设筛选：群系、哨兵、种族、拦截机、最少行星、异常状态；
   - “扫描系统数”是每个区域的系统数（20–767）；
   - 点“扫描”；进度在状态栏/任务栏；可“取消扫描”（当前系统完成后停止）；
   - 结果进入“扫描结果”标签，并写入本地银河索引。
5. 银河索引：
   - 在“银河索引”标签里按条件“查询”，最多显示 500 行；
   - “导出结果”/顶部“导出 CSV”把当前筛选结果写成 CSV；
   - 可复制选中行的符文串。
6. 选中一条带符文串的行后：
   - “复制 符文串 / 复制坐标”；
   - “浮窗显示符文”；
   - “定位并填入传送”只是把符文填进“游戏内代理”页的输入框，**不会传送**。

地址工作台：

- 输入 12 位符文串（如 `123456789ABC`）→ “解析 符文串”；
- 或输入 `0x…` 种子 → “种子反查”；
- **坐标文本暂不支持直接解析**；
- 种子反查可能得到多个候选，且可能欠定；候选需要生成器证实。

依赖：星图/行星/扫描需要游戏目录与 unicorn（执行 NMS.exe 的星系生成器）；缺游戏或 unicorn 时该模块会明确报不可用，其它功能不受影响。

### 3.5 传送门符文浮窗（含点击穿透）

#### 图形入口

1. 星图里选中一个带符文串的行（行星/扫描结果/银河索引）。
2. 点“浮窗显示符文”。
3. 浮窗会置顶显示 12 个符文；拖动移动，`Esc` 关闭。
4. 把游戏设为“无边框窗口”，把浮窗拖到传送门输入框附近，照着点。

#### 命令行入口

```bash
python -m starforge glyph-overlay 123456789ABC
python -m starforge glyph-overlay 123456789ABC --click-through
python -m starforge glyph-overlay 123456789ABC --alpha 0.9 --tile 72 --scale 1.2
```

- 参数：`--alpha`（默认 0.94，最低 0.3）、`--tile`（每格像素，默认 72）、`--scale`（整体缩放）、`--click-through`（鼠标穿透）。
- 符文串也可以是“地址”；程序会按位段重排成 12 位符文，不是直接截断。
- 点击穿透会同时设置 Qt 的透明输入和 Windows 的 `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`（`starforge/app/overlay.py:20`）。
- **开启穿透后，浮窗收不到鼠标/键盘事件，`Esc` 也就无法关闭**；请结束运行 `glyph-overlay` 的进程（或关闭终端）来收起。
- 浮窗不注入游戏、不读写游戏内存；它只是置顶窗口。

### 3.6 模板 Mod + 表情领取（8 字节种子）

这是 Starforge 的“把外观送进游戏”的路径。它**不使用游戏内代理**，也不碰存档：只改游戏进程里模板槽的 8 字节种子。

#### 它是什么

模板 Mod 为 8 种程序化船型各建一个奖励槽：

| 模板 id | 船型 | 表情标题（简中） | 领到的船名 |
|---|---|---|---|
| `STARFORGE_SENTINEL` | 拦截机 | 星铸 · 拦截机 | 星铸·拦截机 |
| `STARFORGE_FIGHTER` | 战斗机 | 星铸 · 战斗机 | 星铸·战斗机 |
| `STARFORGE_HAULER` | 运输舰 | 星铸 · 运输舰 | 星铸·运输舰 |
| `STARFORGE_EXPLORER` | 探索舰 | 星铸 · 探索舰 | 星铸·探索舰 |

#### 第一步：安装模板 Mod（应用内一键）

**推荐路径**：游戏内代理 → “安装模板 Mod”。

1. 先在设置页配置游戏根目录（必须含 `Binaries/NMS.exe` 与 `GAMEDATA/PCBANKS`）。
2. 点“安装模板 Mod”，确认后写入 `<游戏目录>/GAMEDATA/MODS/starforge-templates/`。
3. 看到成功提示后**重启游戏**；这是数据 Mod，不走 pymhf/注入。
4. 想卸载就点“打开 Mods 目录”删除 `starforge-templates` 文件夹。

代码依据：`[代码] starforge/app/pages/game_link.py:303-311`、`:984-1012`；
`[代码] starforge/services/__init__.py:1262-1289`。
注意：这一步会写游戏目录，目前只要求 `confirm=true`，**不检查**存档写开关。

**备用路径**（一键安装失败/想先看文件时）：

- 源码模式：`python -c "from starforge.live import exml; print(exml.write_mod(r'<缓存目录>\\starforge-mod')['path'])"`
- 本地 JSON API：`POST /api/live/template-mod`，body 里给 `dest`；
- 生成后把整个 `starforge-templates` 文件夹复制到 `<游戏目录>/GAMEDATA/MODS/`。

最终应形如：

```text
<游戏目录>/GAMEDATA/MODS/starforge-templates/METADATA/REALITY/TABLES/REWARDTABLE.EXML
```

#### 第二步：确认 Mod 已生效

重启游戏后，表情菜单里应出现 8 个“星铸 · …”表情；`GAMEDATA/MODS/starforge-templates` 下应有
`REWARDTABLE.EXML`、`EMOTEMENU.EXML`、`PLAYERCHARACTER.ENTITY.EXML`、`LocTable.mxml` 和 8 张 DDS。

注意：

- 数据 Mod 使用 `_id` 合并语义；如果你还装了别的修改 `REWARDTABLE` / `EMOTEMENU` / `PLAYERCHARACTER` 的 Mod，可能互相覆盖，请只保留一个。
- 卸载就是删掉 `starforge-templates` 文件夹。
- Mod 不含游戏原始文件；模板参数仍可能随游戏版本变化。

#### 第三步：应用内“送进游戏”

1. 确认游戏**正在运行并已进入存档**（不是主菜单）。
2. 确认模板 Mod 已安装并重启过。
3. 在“飞船实验室”或“我的船队”里选中一艘飞船。
   - 只有模板清单里的 8 种船型会启用“送进游戏”按钮；
   - 固定模型/其它船型没有模板槽，按钮不可用。
4. 点“送进游戏”。程序会：
   - 检查种子不是 `0x0`；
   - 确认平台是 Windows、游戏在运行；
   - 在游戏内存里搜索出厂种子（`STARFOR` + 槽位序号），并检查附近是否出现该槽的 `Slots` 值（120–127）；
   - 只有“命中唯一且自洽”才写；多个候选同样可信时**拒绝写入**；
   - 写入后立刻回读校验；不符就报错，不反复重试。
5. 成功后提示“已写入「星铸 · X」模板，去游戏表情菜单选它领取”。

#### 第四步：游戏内领取

1. 打开游戏的表情菜单。
2. 找到“星铸 · 拦截机/战斗机/…”等 8 个表情之一。
3. 选中它。游戏会发放对应船型的飞船：
   - 船名固定为“星铸·X”；
   - 默认 S 级、较大库存，并附带 4 项科技（发射器、飞船跳跃、超光速引擎、护盾）；
   - **外观由该模板当前的种子决定**，也就是你刚才“送进游戏”的种子。

#### 重要限制

- 只改**内存里的 8 字节种子**；不改存档，不改 Mod 文件。
- **重启游戏后**，模板槽回到 Mod 里的出厂种子；想再次领取就再“送进游戏”一次。
- 写入需要打开游戏进程的读写权限；权限不足时会提示以管理员身份运行。
- 定位失败常见原因：
  - 没装模板 Mod，或装了没重启；
  - 还没进入存档；
  - 游戏版本变化导致布局不同；
  - 同时装了会改这些表的其它 Mod；
  - 多个候选同样可信（保护机制，拒绝写入）。
- 这不是“把船直接塞进存档”，而是“让游戏自己发一艘船给你”；领到后是否保存由游戏决定。

### 3.7 传送到星球（传送门机制）

这是“从星图/同伴来源星球一键传送到目标行星”的路径，走游戏自己的
`cGcPortalComponent`，不是模拟按键。

#### 前置条件

1. 游戏正在运行，agent 已连接，且已进入存档（不是主菜单）。
2. 当前不是多人模式；多人时传送/还原/扫描写一律拒绝。
3. 目标有合法的 12 位门地址（星图扫描结果/地址工作台能生成）。
4. **未验证 build 需要显式打开 `allow_unverified_agent`**：随包 `builds/185034.json`
   仍是 `unverified`，默认返回 `E_BUILD_UNVERIFIED`（见设置项说明）。
5. 先备份存档；传送失败可用“还原上一次传送”或存档备份回滚。

#### 操作

- **星图**：选中一条能生成合法门地址的扫描结果 → “传送到此星球” → 二次确认。
- **游戏内代理页**：填符文地址 → 传送方式选“传送门效果” → “传送到此地址”。
- **同伴页**：选中同伴 → “传送到来源星球”（来源 UA 能解出符文时才启用）。

#### 预期与限制

- 默认 `stage=prepare_warp`，已实测能传送到目标行星；`warp_only` 无效，`full` 未测。
- 传送前 agent 会先写 `~/.starforge/agent/snapshots.json`；写不进去就取消传送。
- 应用会轮询 `/player` 读回位置：portal 最多等 **40 秒**，普通“写位置”是 3 秒。
  读回失败只说明“未确认”，不等于命令没执行；不要连续重试。
- 普通“写位置”传送（`/teleport`）仍保留，但它只是改 UA + 触发本地加载，
  持久性依赖游戏自身加载流程，不能当传送门效果。

来源：`[代码] starforge/agent/starforge_agent.py:838-909`、`:1327-1367`；
`[代码] starforge/services/__init__.py:1065-1073`、`:1094-1127`；
`[实测] docs/AGENT-INJECT-CRASH.md §14`。

## 4. 游戏内代理（agent）

### 4.1 它是什么

- 它是一个 **pymhf + NMSpy 的 Python Mod**（`starforge/agent/starforge_agent.py`），不是 DLL。
- 应用把 Mod 复制到 `~/.starforge/agent/starforge_agent.py`，用 pymhf 注入 `NMS.exe`；pymhf 在本机 `127.0.0.1:5000` 提供 HTTP API，应用通过 `AgentClient` 调用。
- 仅 Windows；默认不安装、不启动；可停止/删除。
- 运行时是独立的 Python 环境，正常发布包内置；缺失时“修复运行时/游戏内组件”会联网安装。

### 4.2 页面怎么用

1. 打开“游戏内代理”（`Ctrl+5`）。
2. 看三步芯片：
   - 1 运行时：运行时文件是否就绪；
   - 2 游戏内组件：NMSpy/pymhf/HTTP API 是否完整；
   - 3 游戏内代理：本机 HTTP 是否可达。
3. 缺组件时点“修复运行时/游戏内组件”；它只修代理运行时，不安装模板 Mod。
4. 进入游戏并载入存档后，按当前版本的实验流程尝试连接（见 4.4）。
5. 连接成功后：
   - “实时遥测”四个按钮读取玩家/星系/行星/船槽；
   - “实时资产”自动读取多功能工具、货船/舰队、同伴（只读）；
   - “读取行星档案”读天气、哨兵、资源、动植物与生物 ID；
   - “安全区”可尝试传送/还原/扫描，但受 build 与多人闸门限制；
   - “附近兴趣点”当前未校准，不会伪造结果。
6. “停止注入器”只停止本应用启动的 launcher；如果 agent 已经注入游戏，彻底停用需要重启游戏（`starforge/live/agent_install.py:754`）。

### 4.3 能力与闸门

界面暴露的能力（`starforge/services/__init__.py:936`）：

| 能力 | 说明 | 风险 |
|---|---|---|
| `player` | 读取玩家 UA/坐标/位置 | 低 |
| `system` | 读取当前星系/行星表 | 低 |
| `planet` | 读取当前行星天气/资源/动植物 | 低 |
| `planet.scan` | 读取当前行星完整档案（实验只读） | 中 |
| `ships` | 读取游戏内 12 个船槽 | 低 |
| `multitool` | 读取多功能工具 6 槽 + 当前槽（`SaveToData`） | 低 |
| `freighter` | 读取货船、货船槽与护卫舰（`SaveToData`） | 低 |
| `pets` | 读取同伴 30 槽（`SaveToData`；当前出战索引不可用） | 低 |
| `scan` | 读取行星扫描数据 | 中 |
| `teleport` | 写位置并触发加载；可用 restore 还原 | 高 |
| `teleport.portal` | 实验：传送门效果；`prepare_warp` 已实测可用 | 高 |
| `restore` | 还原上一次传送快照 | 中 |
| `scan.instant` | 游戏内扫描条立即完成 | 中 |
| `scan.discover` | 写发现列表（界面未提供入口） | 高 |

> 注意：`starforge agent hello` 的 CLI 能力表仍是旧的 13 个抽象名字
> （`ship.write_seed`、`debug.flags` 等），和 agent 的 15 个 HTTP 端点**不是一一对应**。
> 排查时以 `/hello` 的 `capabilities` 和 `live_capabilities()` 为准；
> `ship.write_parts`、`debug.flags` 永远不可用。

闸门顺序：

1. **未连接**：全部不可用；
2. **build 未验证**：只读能力可用，高风险写不可用；
3. **多人模式**：高风险写强制禁用；
4. **`allow_unverified_agent`**：只对 `teleport`、`restore`、`scan.instant`、`teleport.portal` 放行实验写；`scan.discover` 不在这个白名单里。

随包地址书里的 build `185034` 状态是 `unverified`（`starforge/live/builds/185034.json:8`），所以默认情况下**高风险写全部被 build 闸门挡住**，即使 agent 连上也只能读。

### 4.4 当前已知限制（重要）

以 `docs/AGENT-INJECT-CRASH.md` 的实测结论为准：

1. **特定注入场景会被识别为“模组冲突”并退出。**  
   已确认出现在“每帧补绑 hook”“pymhf 直接拉起进程被 Steam 接管”等场景；游戏内弹“检测到潜在模组冲突问题”，退出后没有崩溃转储、没有 Application Error、也不写 `DISABLEMODS.TXT`。不同场景不能一概而论，去掉每帧补绑后可存活（文档第 12、13 节）。
2. **attach 注入默认被代码拒绝。**  
   直接附加到已初始化的 `NMS.exe` 实测会在 `python311.dll` 访问冲突（`starforge/live/agent_install.py:605`）。只有调试时可用 `STARFORGE_ALLOW_ATTACH_INJECT=1` 强制。
3. **“启动游戏并注入”仍可能被游戏关闭。**  
   这条路径使用 `start_paused=True`，注入后观察约 6 秒；如果游戏已经退出，会返回 `E_GAME_EXITED`，并明确提示（`starforge/live/agent_install.py:729`）。不要反复重试。
4. **“连接游戏”已改为不替用户启动游戏。**  
   页面会先检测 `NMS.exe` 是否在运行，再走 `attach=False`（`services.agent_connect()`）；它不是 `attach=True` 的强注。稳定读取仍建议“Steam 启动 → 主菜单/存档 → 连接 → 进/出一次存档触发绑定”。
5. **端口固定。** pymhf 目前固定监听 5000；被占用时会报错。`STARFORGE_AGENT_PORT` 只在 runtime 支持时生效。
6. **token 可能退化为 disabled。** 游戏由 Steam 启动时不一定继承环境变量；代码会把 token 同时写到 `~/.starforge/agent/token`，但实测仍可能出现 `auth: disabled`。服务只监听 `127.0.0.1`，风险有限，但不要把“有 token”当成一定生效。
7. **`/ships` 的校准依赖版本。** 当前文档记录已在某个存档上逐位核对 4 艘船；换 build/换版本仍可能读空或不一致。
8. **兴趣点扫描未实现/未校准。** 页面按钮已禁用并标注“未实现”，不会再发必败的 `scan.poi`；不会伪造坐标。

**结论：** 在换用完整版运行时并实机验证、且游戏不再判定模组冲突之前，不要把游戏内代理当作稳定功能；**不要在你的真实存档上反复尝试注入**。

### 4.5 不装 agent 也不影响哪些功能

以下全部不需要游戏内代理，也不需要注入：

- 按部件/涂装搜索、结果浏览、对比、收藏、分享码；
- 真 3D 预览、部件 3D 预览、渲染图、截图、glb 导出；
- 存档读取、船队/同伴/护卫舰/工具/货船查看；
- 同型换种子、改船级/属性、改货币/名称/涂装、扩展编辑；
- 备份/恢复/批量导出；
- 星图当前星系、行星表、本星船池、银河扫描、索引查询、CSV 导出；
- 地址工作台、符文浮窗；
- **模板 Mod + “送进游戏” + 表情领取**（它走外部内存，不走 agent）；
- `doctor` / `selftest` / `selfcheck` / `live probe` 等诊断。

只有“实时遥测、行星档案、传送/还原、游戏内扫描、兴趣点”这些依赖 agent。

## 5. 设置项逐条解释

设置保存在 `~/.starforge/settings.json`；修改方式有三种：设置页、`starforge settings` 命令、直接编辑 JSON（需重启应用生效）。

| 设置项 | 默认值 | 在哪里改 | 作用与影响 |
|---|---|---|---|
| `write_enabled` | `false` | 设置页 / `settings --write` | 写存档的总开关。关闭时所有写接口/服务抛 `WriteDisabled`（HTTP 403）。 |
| `confirm_writes` | `true` | 设置页 | 是否在每次写前弹二次确认。关闭只会少弹确认框；写入开关、备份、读回、回滚仍在。服务层/HTTP 的 `confirm=true` 仍必须提供。 |
| `saves_dir` | `""` | 设置页 / `settings --saves` | 空 = 自动解析：`STARFORGE_SAVES` → 平台默认目录中含 `*.hg` 的 `st_*`。填了但目录不存在时解析为空。 |
| `gamedata_dir` | `""` | `settings --gamedata` / 环境变量 | 可选的 Gagarin `GAMEDATA`，必须含 `Gagarin/ships/catalog.txt`。显式路径无效会回退自动发现；**设置页没有这个输入框**。 |
| `game_dir` | `""` | 设置页 / `settings --game` | 游戏根目录（含 `Binaries/NMS.exe` 与 `GAMEDATA/PCBANKS`）。影响 L1 真 3D、星图生成、代理启动；为空时 3D 降级为 L0。 |
| `backup_keep` | `0` | 设置页 | 每次写入产生的备份最多保留多少份；`0` = 永不自动删除。设置 `>0` 时只保留最新的 N 份 `*.bak`。 |
| `workers` | `0` | 设置页 / 实验室 | 搜索/扫描的偏好线程数；`0` = 自动。实验室会把值限制在允许范围：发布包 1；源码默认 4，最多 8（受 CPU 核数限制）。 |
| `port` | `0` | `serve --port` / `settings.json` | 只影响可选的本地 JSON API；`0` = 随机空闲端口。原生窗口不监听任何端口。 |
| `theme` | `"dark"` | 仅 JSON | 目前是保留字段，界面固定深色主题，**未参与主题切换**。 |
| `allow_unverified_agent` | `false` | 代理页复选框 / JSON | 允许在未验证 build 上尝试实验写（teleport/restore/scan.instant/teleport.portal）。不解除多人限制，也不在实验白名单里放行 `scan.discover`。风险很高，默认不要开。 |

环境变量（优先级高于/补充设置）：

| 变量 | 作用 |
|---|---|
| `STARFORGE_HOME` | 应用数据目录，默认 `~/.starforge` |
| `STARFORGE_SHIPWRIGHT` | NMS-Shipwright 仓库根（源码模式） |
| `STARFORGE_GAMEDATA` | Gagarin `GAMEDATA` 根 |
| `STARFORGE_SAVES` | 存档目录 |
| `NMS_DIR` | 游戏根目录（自动检测优先读它） |
| `STARFORGE_AGENT_PORT` | 代理端口（仅 runtime 支持时生效） |
| `STARFORGE_ALLOW_ATTACH_INJECT=1` | 强制允许 attach 注入（仅调试，风险自负） |
| `STARFORGE_SAFE=1` | 等同于 `app --safe`：软件 OpenGL |

查看当前值：

```bash
python -m starforge settings
```

命令只打印 `write_enabled / saves_dir / gamedata_dir / game_dir / port`，但可以通过参数修改 `--saves/--gamedata/--game/--write`。

## 6. 安全与数据

### 6.1 写入的四道闸

1. **总开关默认关闭**：`write_enabled=false` 时，服务层 `require_write()` 直接拒绝（`starforge/core/settings.py:147`），HTTP 返回 403。
2. **二次确认**：每个写对话框都走 `ask_write()`；`confirm_writes=false` 时跳过弹窗，但后端仍要求 `confirm=true`（`starforge/app/dialogs/confirm.py:10`）。
3. **游戏必须退出**：写入前检测 `NMS.exe`/`No Man's Sky` 进程；检测到就拒绝，避免被游戏覆盖。检测是尽力而为，检测不到时不会阻止。
4. **目标校验**：同型、程序化、槽位存在、种子有效；跨型/固定模型/空槽都会拒绝。

### 6.2 备份、原子写、读回、回滚

- 备份：写前复制为 `<存档名>.<YYYYmmdd-HHMMSS-ffffff>.bak`，默认永不删除。
- 原子写：先写 `<存档>.part`，`flush` + `fsync`，再 `os.replace` 替换；不会出现“写了一半的存档”被当成正式文件（`starforge/save/writer.py:89`）。
- 读回：写后重新解码存档，核对目标种子/等级/名称/涂装；改级还会核对其它船种子未动。
- 回滚：任一步失败，把写入前的原始字节原子写回；备份保留。
- 恢复：从备份恢复前会再留一份当前快照；只接受与当前存档同名前缀的备份。

### 6.3 “写入副本”的语义

- `save.hg` → 复制成 `save.edited.hg`，只改副本，原档一字节不动。
- 传入的已经是 `.edited.hg` → 直接原地写，不再复制。
- 各对话框默认值不同：
  - 实验室“写入存档”：默认**不勾**副本；
  - 设计器“写入存档”：默认**勾选**副本；
  - 船级/属性、存档编辑、扩展编辑：默认**勾选**副本。
- 想进游戏验证副本：先备份原档，再把 `save.edited.hg` 改名成 `save.hg`/`save2.hg`。

### 6.4 内存通道的安全语义

- “送进游戏”只写 **8 字节**（u64）种子到模板槽，不写存档、不写游戏代码。
- 这条通道**不经过存档写入开关 `write_enabled`，也没有二次确认对话框**；它的保护是“只写 8 字节 + 候选唯一 + 写后回读”。不想写内存就不要点这个按钮。
- 定位依据：出厂种子 + 附近 `Slots` 值自洽；多个候选同样可信时**拒绝写入**。
- 写入后立即回读；不一致就报错，不猜地址、不重试。
- 只读诊断 `live probe` 不写内存；但它打开进程时请求了读写权限，权限不足会提示管理员。
- 游戏重启后模板槽恢复出厂种子。

### 6.5 网络与隐私

- 原生界面默认不联网，不上报遥测。
- 只有你主动“修复运行时/游戏内组件”时，才会访问 python.org / bootstrap.pypa.io / PyPI 下载 Python 运行时与依赖。
- 可选的 `starforge serve` 只监听 `127.0.0.1`，并校验 `Host`/`Origin`，防止 CSRF/DNS rebinding。
- 诊断包会脱敏 token/密码等字段，并只包含最近的日志尾部。

### 6.6 为什么杀软可能报警

Starforge 会做两件杀软启发式重点关注的事：

1. **读/写其它进程内存**（仅在你显式点“送进游戏”、`live probe` 或代理时）：`OpenProcess` + `ReadProcessMemory` / `WriteProcessMemory`（`starforge/live/mem.py:195`）。
2. **修改你自己的存档文件**：备份、原子写、读回；这不是病毒行为，但和勒索/篡改启发式相似。

此外，发布包是 PyInstaller 打包的 Python 程序，内置 Python DLL/运行时；部分杀软会把“打包的 Python + 进程内存访问”误判。若 NumPy DLL 被拦截，启动会提示重新解压完整包并加排除项（`starforge/app/main.py:116`）。

### 6.7 卸载与清理

- 删除发布包目录即可卸载程序。
- 删除 `~/.starforge` 可清掉设置、收藏、历史、缓存、代理运行时。
- 存档旁的 `*.bak` 不会自动删除；确认不需要后手动清理。
- 模板 Mod：删除 `<游戏目录>\GAMEDATA\MODS\starforge-templates`。

## 7. 排障

### 7.1 `doctor`：环境体检

```bash
python -m starforge doctor
# 发布包：
starforge-cli.exe doctor
```

输出是 JSON，重点看：

- `deps`：`numpy / flask / lz4 / hgpaktool / texture2ddecoder / pefile` 是否 `ok`；`capstone` 是可选开发依赖；
- `unicorn.ok`：不仅 import，还会真的创建 `Uc` 并 `mem_map`；失败会导致星系/行星生成和种子反查不可用；
- `systemgen.available`：星系生成器能否借用；
- `gui.available`：PySide6/Qt 是否可用；
- `upstream`：NMS-Shipwright 是否可导入；
- `gamedata.valid`：是否含 `Gagarin/ships/catalog.txt`；
- `notes`：每条都是可执行的修复建议；
- `ok`：全部关键项通过才为 `true`；失败时命令退出码为 **7**。

注意：`doctor` 把 GAMEDATA 视为必需项。如果你走“纯游戏资源”模式（没有 Gagarin 数据），它可能报 GAMEDATA 无效并退出 7，但部件树仍可从游戏 pak 推导，搜索/3D 仍可用。此时以 `selftest` 和实际页面为准。

设置页的“运行体检”是**轻量版**：只检查依赖导入与健康摘要，不计算 `ok`，即使缺依赖也可能显示“体检完成：通过”；请逐条看依赖和健康检查，不要只看标题。

### 7.2 `selftest`：路径与数据自检

```bash
python -m starforge selftest
```

典型输出：

```text
Shipwright: <Shipwright 仓库>  [同机仓库]
GAMEDATA  : <GAGARIN GAMEDATA>
  catalog: {...}
  icons  : {...} 版本 [...]
  样本图 : [...]
存档      : <存档目录> 12 个文件
```

怎么读：

- `Shipwright` 显示“未找到” → 源码模式没配 `STARFORGE_SHIPWRIGHT`；发布包应显示“内置(打包版)”；
- `GAMEDATA` 显示“未找到” → 只是没有 Gagarin 数据；若游戏目录可用，部件仍可从游戏资源推导；
- `catalog/icons` 只在有 GAMEDATA 时打印；
- 最后一行是存档目录与 `*.hg` 文件数，不代表都能读。

`selftest` 主要用于看路径，不测试 3D/写入；正常路径下返回 0，失败信息要靠文字判断，而不是退出码。

### 7.3 `selfcheck`：端到端自检

```bash
python -m starforge selfcheck
python -m starforge selfcheck --no-write
```

输出每一步的 `✓ / ! / ✗`：

- `✓`：通过；
- `!`：非关键步骤失败（例如非 Windows 的实时通道状态）；
- `✗`：关键步骤失败，命令退出码为 1。

步骤包括：部件目录、图标、读存档、搜索种子、3D + glb、缩略图、符文面板、星系生成、写入（**只在临时副本上**）、实时通道状态。

注意：

- 写入测试会把存档复制到临时目录，临时打开写开关，写完再恢复原设置；**不碰真实存档**。
- 但它会先执行一次 `settings.autodetect(apply=True)`，可能自动填入空/无效路径，等同于点了一次“自动检测”。
- 有步骤失败时，按输出末尾的顺序排查：设置页路径 → `selftest` → 日志。

### 7.4 `agent hello` 与 `live probe`

```bash
python -m starforge agent hello
python -m starforge live probe
```

`agent hello` 输出：

- `agent.installed / installed_path`：Mod 文件是否在 `~/.starforge/agent/`；
- `agent.runtime`：pymhf/NMSpy 是否就绪；
- `agent.reachable`：本机 HTTP 是否可达；
- `capabilities`：CLI 的 13 项**抽象**能力及不可用原因；它们和 agent 的 15 个 HTTP 端点
  不是一一对应（排查以 `/hello` 的 `capabilities` / `live_capabilities()` 为准）；
- `build`：build id、status、verified、write_allowed；
- 未连接时退出码为 **5**。

`live probe`（模板槽只读诊断）输出：

- `scan`：扫描的区域数、字节数、耗时、线程数、是否被 `max_regions` 截断；
- `types[]`：每种船型的候选地址/得分、`chosen`、`confidence`、`reason`；
- `structural`：结构兜底候选（仅排障，不参与写入）；
- `hint`：明确“本接口只读”。

怎么读 `reason`：

- “可写入”：唯一且自洽，可以尝试 `live push` 或应用内“送进游戏”；
- “没有命中：模板 Mod 可能没装/没生效”：先装 Mod/重启/进存档；
- “命中多处但都缺少 Slots 佐证”：布局不对或扫描不完整；
- “命中多个同样可信的候选，写入会被拒绝”：保护机制，别强行写；
- “这次扫描被 max_regions 截断”：内存区域太多，可能漏扫。

### 7.5 日志与诊断包

- 主日志：`~/.starforge/logs/starforge.log`（2 MB 滚动，3 份）；
- 原生崩溃栈：`~/.starforge/logs/faulthandler.log`；
- 代理启动日志：`~/.starforge/agent/launcher.log`；
- 游戏崩溃转储（如果发生）：`%LOCALAPPDATA%\CrashDumps\NMS.exe.<pid>.dmp`。

设置页：

- “复制最近日志”：读取最近 5 个日志的尾部并复制（已脱敏）；
- “查看 launcher.log 摘要”：只读显示；
- “导出诊断包”：ZIP 内含 `health.json / doctor.json / build.json / agent.json / settings.json / selfcheck.json / logs / manifest.json`；凭据字段会替换成 `***`。

### 7.6 常见错误与处理

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 数据层 ✗ / 读不到部件表 | 游戏目录未设置，且没有 Gagarin 数据 | 设置 → 自动检测/选择游戏根目录；或配置 `STARFORGE_GAMEDATA` |
| 3D 只显示渲染图 | 游戏目录未设置，或 `GAMEDATA\PCBANKS` 不可读 | 设置正确游戏根目录；确认 pak 完整；看 `doctor` 的 `gui/upstream` |

| 原生界面启动失败 | PySide6 缺失/损坏、显卡驱动 | 重装完整包；`app --safe` 用软件 OpenGL；跑 `doctor` |
| 启动弹“NumPy 不可用” | 杀软拦截/旧文件覆盖 | 解压到全新目录；把安装目录加入杀软排除项 |
| “写入功能当前关闭” / 写入按钮灰 | `write_enabled=false` | 设置 → 允许写入存档 |

| “没有找到模板槽” | 模板 Mod 未装/未重启/未进存档 | 装 Mod → 重启 → 进存档；再 `live probe` |
| “模板槽命中多个同样可信的候选” | 多份模板/布局冲突 | 只保留一个模板 Mod；不要强行写 |
| “打不开进程 NMS.exe” | 权限不足/游戏未启动 | 以管理员身份运行；确认游戏已启动 |
| “先启动游戏并进入存档，再送进游戏” | 游戏未运行/在主菜单 | 进存档后重试 |
| “不支持附加到已运行的游戏注入” | attach 注入默认拒绝 | 不要用默认连接；见第 4 节，实验需显式开关 |
| `E_GAME_EXITED` / 游戏弹“模组冲突” | NMS 主动关闭注入 | 不要反复重试；改用离线功能/模板槽 |
| “agent 端口 5000 已被占用” | 其它进程占用 | 关闭占用进程；或等 runtime 支持改端口 |
| “多人模式已启用：高风险写操作被禁用” | 代理检测到多人 | 单机使用；不要绕过 |
| `accountdata.hg` 读不出船 | 账号数据不是玩家存档 | 选 `save.hg` / `save2.hg` |
| `mf_*.hg` 读不出船 | 清单文件不含飞船 | 忽略，不是存档 |
| 搜索 0 结果 | 条件太严/预算太小 | 减少“不要”、放宽涂装容差、提高预算 |

| 符文不是游戏原图 | 缺 BC7 解码器或 `NMSUI` pak | 仍可用位图字体；装 `texture2ddecoder` 并确认游戏目录 |
| 模板表情菜单没有新增项 | Mod 没放对/被其它 Mod 覆盖/没重启 | 检查 `GAMEDATA\MODS\starforge-templates`；只留一个改表的 Mod |

## 8. 常见问题（FAQ）

**Q1. 为什么不能把 A 船型的外观套到 B 船型上？**  
因为种子的含义由船型/模型决定；同一个种子在另一型上会长成完全不同的船。写回会强制同型；设计器“替换槽位”是整艘船换成目标船型，不是移植外观。

**Q2. 为什么游戏开着不能写存档？**  
游戏加载存档后会在内存里持有状态，退出时可能覆盖你刚写的文件。程序检测到 `NMS.exe` 会拒绝；请完全退出游戏再写。

**Q3. 写入成功，但进游戏没变化？**  
先确认是不是写进了 `save.edited.hg` 副本；副本不会自动被游戏读取。把副本改名成 `save.hg`/`save2.hg` 前先备份原档。另外，固定模型船改种子不会改变外观。

**Q4. 备份在哪里？怎么恢复？**  
在存档同目录，文件名形如 `save.hg.20261121-221500-123456.bak`。船队 →“备份恢复” → 选备份 →“恢复所选”。默认永不自动删除备份。

**Q5. 为什么搜索只有 1 个线程？**  
发布包为了避免 Windows 多进程搜索卡在 0 种子，固定 1 线程；源码模式默认 4，最多 8。预算和条件比线程数更影响命中率。

**Q6. 为什么 3D 变成了图片？**  
说明当前是 L0：没有配置游戏目录，或读不到 `GAMEDATA\PCBANKS` 里的模型。配好游戏根目录后重试；这不影响搜索和存档功能。

**Q7. 为什么“导出 glb”失败？**  
glb 需要 L1 真 3D；L0 渲染图无法导出模型。先确认游戏目录和 pak 可读。

**Q8. 符文图和游戏里不一样？**  
程序优先解码游戏里的 `portalsymbol.*.dds`（BC7）；缺 `texture2ddecoder` 或 pak 时会退回内置位图字体。数字/顺序仍按同一套位段重排，不影响你照着点。

**Q9. 模板 Mod 装好后，表情菜单没有“星铸”？**  
检查：是否复制到了 `<游戏>\GAMEDATA\MODS\starforge-templates`；是否重启游戏；是否还有别的 Mod 改 `REWARDTABLE/EMOTEMENU/PLAYERCHARACTER`。只保留一个。

**Q10. “送进游戏”成功，但重启游戏后船又变回去了？**  
“送进游戏”只改游戏进程内存里的 8 字节模板种子，不改 Mod 文件/存档；重启后模板槽回到出厂种子。需要再送一次。

**Q11. 为什么“连接游戏”提示不支持附加注入？**  
attach 注入在 build 185034 上实测会让 `NMS.exe` 在 `python311.dll` 访问冲突；代码默认拒绝，只有 `STARFORGE_ALLOW_ATTACH_INJECT=1` 可强制调试。即使强制，NMS 也可能把注入识别为模组冲突并退出。

**Q12. 不装游戏内代理，会少什么？**  
只少“实时遥测、行星档案、传送/还原、游戏内扫描、兴趣点”。搜索、3D、存档读写、星图、符文、模板 Mod/表情领取都不受影响。

**Q13. 为什么不能读 `accountdata.hg` 或 `mf_*.hg`？**  
前者是账号数据，没有飞船列表；后者是游戏清单文件，不含玩家数据。请选 `save.hg`/`save2.hg`。

**Q14. 可以改货船/护卫舰/多用途工具吗？**  
当前只读：可以看名称、类型、等级、属性、种子，但不提供写回；扩展编辑里也没有伪造这些写入。

**Q15. 支持多人模式吗？**  
不做联机同步；代理检测到多人会禁用高风险写。存档写入只改本地文件，联机状态下使用风险自负，建议单机。

**Q16. 为什么杀软报警？**  
程序会读写游戏进程内存（模板槽/代理）并修改你自己的存档，还带打包的 Python 运行时；这些都是启发式重点。默认不联网、不驻留、不开机自启；不放心就只用搜索/3D/星图/符文。
