# 第一部分 产品

## 1.1 一句话

**nmshunter 是无人深空的"星际情报台"**：帮你找到想要的飞船与星球、先看 3D 效果、再把它拿到手——全程本地运行，不改游戏代码、不碰多人、写入前自动备份。

## 1.2 四个用户与四个场景

| 人设 | 目标 | 主路径 |
|---|---|---|
| 找船党 | 就要那艘"V 型分裂机翼 + 毒刺机头"的拦截机 | 搜索 → 网格浏览 → 3D 确认 → 写回存档 |
| 晒图党 | 把 7 艘船做成图/模型发出去 | 我的船 → 批量渲染 PNG / 导出 glb |
| 探索党 | 找 Lush + 无哨兵 + 能刷拦截机的星系 | 星球搜索 → 结果表 → 符文浮窗 |
| 收藏党 | 知道本星系会刷什么 | 当前系统 → 船池表（50 条） |

## 1.3 六条设计原则

1. **先算后连**：能在离线算出来的（种子、型号、星球、船池）绝不依赖游戏运行。
2. **降级有名字**：看得见的是哪一档（L0 部件图 / L1 真 3D / L2 游戏内），不允许静默降级。
3. **写入必可逆**：备份 → 原子写 → 读回 → 回滚，四步缺一不可；默认只读。
4. **一屏一件事**：每页只有一个主动作；长任务进任务条，不阻塞界面。
5. **诚实的时间**：ETA 按实测速率给（搜索 13–20 M/s、系统 25/s、单船 0.4–1.2 s），不承诺做不到的（如离线扫描星球生物）。
6. **版本可诊断**：三层（格式/布局/地址）各自自检，坏了只关一项并说清楚。

## 1.4 能力边界

| 能做 | 不能做（并说明原因） |
|---|---|
| 按部件/涂装搜种子（同型内） | 跨型移植外观（`seed` 与 `type` 绑定，物理不可行） |
| 真 3D 预览、导出 glb/PNG | 改玩家位置/货币/物品（只碰"船的外观"） |
| 读存档船、同型换 seed、备份回滚 | 离线扫描星球生物（无生物生成器；存档无清单） |
| 星系/星球批量搜索 + 符文地址 | 多人模式任何写入 |
| 本星系船池（含拦截机种子） | 注入改游戏代码（不做；参考项目仅作"游戏内读取"的备选后端） |

## 1.5 与三个参考项目的关系

| 项目 | 我们借什么 | 我们不借什么 |
|---|---|---|
| **NMS-Shipwright** | 生成算法、几何/涂装、存档读写、系统生成（作为库，路径依赖） | 它的每请求开进程、非原子写、零鉴权 |
| **Gagarin_Titov** | 部件目录 `catalog.txt`、真实缩略图 `icons.bin`、设置/日志思路 | 它的硬版本闸门、自我替换式更新、DLL 注入（可选后端，不是默认） |
| **Super Ship Hunter** | "模板槽 + 外部写"的游戏内落地思路、用数据表常量当签名的技巧 | 它的单签名无容错、只支持两型 |

# 第二部分 设计

## 2.1 总体架构

```
┌────────────────────── 浏览器（127.0.0.1:<随机端口>） ──────────────────────┐
│  搜索  我的船  星球  设置        + 独立浮窗进程（符文面板 / 常驻置顶）      │
└───────────────┬───────────────────────────────────────┬───────────────────┘
                │ JSON API（Host/Origin 校验；写操作 403 闸门）
┌───────────────▼───────────────────────────────────────▼───────────────────┐
│ nmshunter-web（Flask 单进程）                                              │
│  jobs（任务/ETA/取消）· cache（三层索引）· settings · lock · log           │
└───────┬───────────────────────┬─────────────────────────┬─────────────────┘
        │ 只读数据（进程内）    │ CPU 密集（常驻池 N=2）  │ 可选 Live 后端
┌───────▼──────────┐   ┌────────▼──────────────┐  ┌───────▼──────────────────┐
│ data: catalog/   │   │ worker: search /      │  │ live-A 内存只读（SSH 风）│
│ icons / gshi     │   │ system / model        │  │ live-B 进程内（Gagarin风）│
│ save: 读/写/备份 │   │ （进程常驻，收任务）  │  │ 仅读当前坐标/模板槽写入   │
└──────────────────┘   └───────────────────────┘  └──────────────────────────┘
```

## 2.2 进程与并发（实测决定的）

| 决策 | 实测依据 | 后果 |
|---|---|---|
| **常驻 worker 池 N=2** | 短任务开 3 进程要 8.94 s（全是启动开销）；稳态 1 进程 13 M/s、3 进程 20 M/s | 首次点搜索不再等 9 秒 |
| 单进程 RSS 上限 ~300 MB | 建模 274 MB / 系统生成 262 MB | 4 核机器上限 2 并发 |
| pak 解包单飞 | 32 GB 档案，IO 才是瓶颈 | 同一批几何只解一次，其余请求排队 |
| 系统生成串行 | 25 系统/秒（0.039 s/系统热态） | 扇扫按批上报进度，可断点续跑 |

## 2.3 数据模型（唯一真相）

```python
ShipRef   = {type, seed, parts|None, model|None, look|None, name, source, slot, procedural,
             share_code}                       # share_code = "nsh1:"+base64(type|seed|parts)
SystemRef = {ua, galaxy, coords, glyphs, race, planets, moons, dissonant, interceptor,
             ships[], planet_list[], elapsed_ms, source:"save|input|scan"}
PlanetRef = {index, seed, biome, biome_name, sentinels, levels[4]}
StationRef= {galactic_address, voxel[3], hull, seed, count, chosen[]}     # 结构（可选模块）
Job       = {id, kind, status, progress{tested,seconds,eta}, result_ref, cancel}
PreviewAsset = {key, level:"L0|L1", glb_path, png_paths[], verts, tris, build}
GlyphPanel   = {glyphs:"1043FEE69929", digits[12], target{ua,coords,galaxy}, mode}
```

**规则**：层与层之间只传这七个结构；新增字段必须同时更新本表与 API 文档。

## 2.4 四条主流程（时序，文字版）

```
① 搜船
  UI[搜索页] → POST /api/search {ship,want,avoid,look,limits}
    → worker: fastsearch（13–20 M/s）→ 每批结果入 Job.progress
    → UI 轮询 /api/jobs/{id} → 网格卡片（L0 缩略图：/api/icons/{part}.png）
    → 点卡片 GET /api/preview/{type}/{seed} → L1（有 pak）/ L0（无）
    → 主动作：写回存档 或 导出 glb

② 看我的船
  GET /api/ships?path=… → ShipRef[]（7 艘）
    → 列表 → 选中 → /api/preview（L1）→ 与"搜索结果"并排对比
    → 主动作：把这艘的 seed 套到另一艘同型船（POST /api/save/apply）

③ 找星球
  GET /api/system?current=1 → SystemRef（6 行星 + 50 船 + 拦截机）
    → 不满意 → POST /api/system/scan {center, radius, filters} → job
    → 结果表（biome/哨兵/dissonant/拦截机）
    → 主动作：打开符文浮窗（把 glyphs 交给浮窗）→ 游戏内传送门

④ 分享
  任意 ShipRef → /api/share?type=&seed=&parts= → "nsh1:…" 
    → 对方粘贴到搜索页 → 直接预览（不依赖任何服务端）
```

## 2.5 缓存与存储布局

```
~/.nmshunter/
├── settings.json          # 写开关默认 false
├── instance.lock
├── logs/nmshunter.log     # 滚动 2MB ×3
├── cache/
│   ├── version.json       # {exe:[size,mtime], paks:97, shipwright_commit}
│   ├── gamedata/          # pak 抽出的 MBIN（72 MB 起）
│   ├── meshes/            # 派生：网格几何（按 seed+parts 哈希）
│   ├── preview/           # glb / png（按 hash 命名，可整目录删）
│   ├── systems/           # 系统生成结果（按 UA）
│   └── icons/             # 部件缩略图（PNG，按部件名）
└── backups/               # 可选：把存档备份集中（默认仍写存档旁）
```

**规则**：`cache/` 全可删；`settings.json` 与 `backups/` 不可删。缓存键必须含 `version.json` 的指纹。

## 2.6 版本与降级（三层）

| 层 | 检测 | 失败后 | 用户提示（原文） |
|---|---|---|---|
| 格式（pak/MBIN/DDS） | magic + 长度 + `(name_hash,guid)` | 3D 退 L0 | 「游戏档案格式已变更，暂时只能看部件图」 |
| 布局（MBIN 类字段） | `gamemeta` 反射 + 匹配 | 3D 退 L0，存档仍可读 | 「需要更新游戏数据布局」 |
| 地址（exe 偏移） | 冒烟：固定 UA → 比对已知行星/船池 | 星球模块禁用 | 「系统生成暂不可用（游戏版本未适配）」 |
| Live 签名 | 多候选 + 结构打分 | 实时通道禁用 | 「游戏内通道暂不可用，可用符文浮窗」 |

**自检**（启动 0.5 s 内）：上游可导入 → 数据/存档/游戏就绪 → 冒烟结果 → 汇总到 `/api/health` 与「设置 → 诊断」。

## 2.7 安全模型

| 面 | 措施 |
|---|---|
| 网络 | 仅 `127.0.0.1`；校验 `Host`/`Origin`；无 CORS；不监听局域网 |
| 写入 | `write_enabled=false` 默认；`confirm=true` 必填；只允许"同型换 seed"与"模板槽 seed" |
| 备份 | `<存档>.<YYYYmmdd-HHMMSS-micros>.bak`；写前必做；失败自动回滚并给出备份路径 |
| 原子性 | `.part` + `os.replace`；写后重新解码校验（槽位/型号/种子） |
| 隐私 | 不联网（除用户主动检查更新）；日志不含存档内容 |
| 覆盖层 | **不注入**：独立置顶窗口（`WS_EX_TOPMOST`，可切点击穿透），游戏用"无边框窗口"模式即可显示 |
| Live 后端 | A 只读（内存读坐标/种子）；B 进程内（可选，默认关闭，需显式同意并提示版本绑定风险） |

## 2.8 性能预算（实测 → 目标）

| 操作 | 实测 | 目标 P95 | 手段 |
|---|---|---|---|
| 首屏 | — | <300 ms | 内联 CSS/JS、无框架、无网络字体 |
| 本星系面板 | 0.039 s/系统 | <200 ms | UA 缓存 + 预热 |
| 单船 L1 | 0.4–1.2 s（热）/5.8 s（冷） | <1.5 s | 解包预热、网格缓存 |
| 单船 PNG | 1.9 s | <2 s | 单视角、降采样 |
| glb 导出 | 2.7 s / 5.3 MB | <3 s | 复用已构建模型 |
| 搜索 | 13–20 M/s | ETA 误差 <30% | 常驻池 + 批上报 |
| 扇扫 | 25 系统/s/进程 | 1000 系统 <60 s | 2 进程 + 断点续跑 |
| 存档写回 | 0.1 s + 备份 | <400 ms | 流式备份 + 原子替换 |

## 2.9 可靠性

* 单实例锁（PID 校验，陈旧锁自动接管）。
* 任何长任务可取消；取消后不留半成品（临时文件带 `.part` 后缀，启动时清理）。
* 存档损坏三道防线：备份、读回校验、`backups/` 里保留最近 N 份（默认永不删）。
* 崩溃后恢复：启动时扫描 `.part` 文件 → 提示"上次写入未完成，已保留备份"。

# 第三部分 功能手册

> 每项统一模板：**目的 / 输入 / 输出 / 界面 / 实现 / 降级 / 验收**。
> 标记：✅ 已实测可做｜🟡 待实现（M1–M4）｜🔵 可选（Live，M5）

## F01 飞船搜索 ✅
* **目的**：按"长什么样"找种子，而不是按名字。
* **输入**：船型（10 种 `_PROC` 之一）；want[]（必须有的部件）；avoid[]（不要的部件）；可选 look（主色/副色/涂装模式）；上限与时限。
* **输出**：`Job` → 结果流（seed + 部件表）；每批带 `tested/seconds/eta`。
* **界面**：搜索页左侧条件区（船型下拉 + 部件树多选 + 调色板）、右侧结果网格。
* **实现**：`fastsearch.fast_search`（实测 13–20 M/s）；部件合法性用 `catalog.txt` 索引预校验（传错船型的部件即时报错，已在 S1 验证）。
* **降级**：搜索本身不依赖游戏文件；仅在"部件目录缺失"时禁用部件树，退化为"随机种子浏览"。
* **验收**：给定 `sentinel + _PIT_A + _TOPFLAP_A + _WINGS_V`，10 秒内出 ≥3 个种子；每个结果能用 `generator.generate` 复现同样部件。

## F02 结果浏览与排序 🟡
* **目的**：让"看结果"本身高效。
* **输入**：排序键（相关度/稀有度/部件数/发现时间）、筛选（只看完整匹配/包含近似）。
* **输出**：分页结果（虚拟滚动）。
* **界面**：网格卡片（缩略图 + 种子尾 6 位 + 关键部件徽章 + `3D`/`部件图` 角标）；顶部工具栏（排序、密度、导出选中）。
* **实现**：服务端只回"部件 id 列表 + seed"，缩略图由 `/api/icons/<part>.png` 按需取，浏览器缓存。
* **验收**：1000 条结果滚动不卡（首屏 <100 ms，滚动帧率 ≥50 fps）。

## F03 3D 预览（三级） ✅/🟡
* **目的**：确认"是不是这艘"。
* **输入**：`ShipRef`（或存档船）。
* **输出**：`L0` 部件图拼板 / `L1` 可旋转 3D（glb 或 WebGL）/ `L2` 游戏内实物。
* **界面**：右侧预览面板（占 60% 宽），底部视角条（等轴/侧/顶/前），右上角档位徽章 L0/L1/L2，右下角"导出 glb / 导出 PNG / 复制分享码"。
* **实现**：`model3d.ship_model` →（网页）WebGL 或（浮窗/导出）glb；PNG 用 `render_model.py` 同一套着色。
* **降级**：无 pak → L0 并显示提示条「未检测到游戏文件：当前为部件图，非 3D」；几何缺失 → L1 平色（沿用 Shipwright 的材质 `skip` 策略）。
* **验收**：你的 `save.hg` 7 艘船逐艘 L1 成功；首解包 <8 s、热 <1.5 s；glb 可被 Blender/three.js 正常打开。

## F04 我的船（存档图鉴）✅/🟡
* **目的**：把"我拥有的"变成可浏览、可对比的资产。
* **输入**：存档路径（自动发现或手填）。
* **输出**：7 艘船的列表（槽位/型号/种子/名称/是否可改外观）+ 3D 缩略。
* **界面**：「我的船」页：左列表、右详情（大图 3D + 部件表 + 涂装色块 + 操作按钮）。
* **实现**：`nms_save` 读取；`ShipRef.from_save_ship`；`proc_model_matches()` 标注"固定模型，改种子无效"。
* **降级**：无存档 → 空态引导「选择存档目录」；存档不可读 → 明确"账号数据/清单文件不适用"（S1 已实现）。
* **验收**：`save.hg` 显示 7 条、`save2.hg` 8 条，且与游戏内一致（种子逐位相同）。

## F05 同型换种子（写回存档）🟡
* **目的**：把搜到的外观变成自己的船。
* **输入**：目标存档、目标槽位、源 `ShipRef`（必须同型）、确认标记。
* **输出**：备份路径 + 写后校验结果。
* **界面**：「我的船」详情页主按钮「把这艘换成…」，弹出源船选择器（只列同型），二次确认（显示"将备份到 xxx.bak"）。
* **实现**：`settings.require_write()` → 备份 → 改 `Seed`（`ships.set_ship_seed`）→ 原子写 → 重新解码校验（槽位/type/model/seed）→ 失败回滚。
* **降级**：写开关关闭 → 403 并指路设置页；游戏运行中 → 409「请先退出游戏」；类型不匹配 → 400 并解释"跨型不可移植"。
* **验收**：写入后游戏内外观与预览一致；人为中断写入能自动恢复（用备份回滚）；连写 3 次备份齐全。

## F06 送进游戏（实时模板槽）🔵
* **只读探测**（新增）：设置页「探测模板槽（只读）」或 `python -m starforge live probe`，
  报告每种船型命中几处、得分、是否因歧义被拒绝——**不写任何内存**，用于远程排障。
  单次遍历内存即可覆盖 8 种船型（公共 7 字节前缀 + 第 8 字节区分）。
* **目的**：不重载游戏就看到实物。
* **输入**：槽位 id（8 种 `_PROC`）、`ShipRef`、确认标记。
* **输出**：写入成功 + 回读校验值。
* **界面**：预览面板的「送进游戏」按钮（仅在 Live 可用时出现）+ 说明「只改模板种子，不动你的船」。
* **实现**：自研 EXML 模板（8 槽）→ 多候选签名定位槽位 → `WriteProcessMemory` 写 seed → 回读比对。
* **降级**：签名全未命中 → 禁用并提示「游戏版本未适配，可用符文浮窗代替」。
* **验收**：写入后游戏内表情领取，外观与预览一致；游戏更新后签名失败能优雅退出不写。
* **宁可不写的三种情况**：候选缺少 Slots 佐证（得分 <0.6）、多个候选同样可信、回读校验不符。

## F07 星系搜索 ✅
* **目的**：按条件找"值得去"的星系。
* **输入**：中心（当前位置 / 坐标 / glyph）、范围（region 数）、条件（种族 / 行星数 / dissonant / 有拦截机）。
* **输出**：`SystemRef` 列表（ua/coords/glyphs/种族/行星数/dissonant/拦截机种子）。
* **界面**：「星球」页 → 顶部搜索条 + 结果表（可排序、可勾选"加入计划"）。
* **实现**：`systemgen.system(ua, planets=True)`（实测 0.039 s 热身）。
* **验收**：给定中心 + 300 系统预算，60 秒内返回全部 dissonant 星系；结果与存档已知系统一致。

## F08 星球搜索 ✅
* **目的**：按生物群系/哨兵等级找落点。
* **输入**：同上 + biome（Lush/Frozen/Toxic/Exotic/Scorched/Dead/Radioactive…）+ 哨兵等级（none/low/aggressive/corrupted）。
* **输出**：行星级结果（星系地址 + 行星序号 + biome + 哨兵 + seed）。
* **界面**：结果表每行带「符文」按钮（打开浮窗）；支持"复制地址"。
* **实现**：`planet_list` 过滤；扇扫按 128 系统/块缓存，可断点续跑。
* **验收**：实测「150 系统 → 10 颗 Lush，0.9 秒」；重复扫描同区域走缓存 <0.2 s。

## F09 当前位置与星球信息 ✅/🟡
* **目的**：知道"我在哪、这里有什么"。
* **输入**：存档（或 Live 只读）。
* **输出**：当前 UA / 坐标 / glyphs / 星系名 / 种族 / 行星号 / 当前行星的 biome 与哨兵等级 / 本星系全部行星表。
* **界面**：「星球」页顶部信息条 + 行星卡片；无存档时显示「从 Live 读取（可选）」按钮。
* **实现**：`locate.save_location` + `systemgen`；Live-A 可读内存补全"实时位置"。
* **明确不显示**：天气/资源/动植物（需行星级生成，未实现）。
* **验收**：实测 `0x4300FEE69929 / 0128:007D:0668:0043 / 1043FEE69929 / Gek / 6 行星 / dissonant`。

## F10 传送门符文浮窗 ✅（本手册新增，替代"热传送"）
* **目的**：不做高危传送，改为"把该输的符文举到你眼前"。
* **原理**：**传送门符文就是系统地址的 12 个十六进制数字**；游戏内图标资源已确认：
  `textures/ui/frontend/icons/update3/portalsymbol.<0..f>.dds`（16 张，256×256，BC7/DXGI 98）。
* **输入**：任意地址（glyphs 串 12 位）。
* **输出**：置顶浮窗，12 个大号符文 + 地址文本 + 复制按钮。
* **界面**（独立进程，非注入）：
  ```
  ┌──────────────────────────────────────────────┐
  │  ⬡ ⬡ ⬡ ⬡ ⬡ ⬡ ⬡ ⬡ ⬡ ⬡ ⬡ ⬡      [×] [⤢]  │  ← 12 个 64px 符文
  │  1 0 4 3 F E E 6 9 9 2 9                    │  ← 数字对照（学习用）
  │  0128:007D:0668:0043 · Euclid · 第 5 行星    │
  │  [复制符文]  [复制坐标]  [置顶✓] [点击穿透]  │
  └──────────────────────────────────────────────┘
  ```
  * 窗口属性：`WS_EX_TOPMOST | WS_EX_LAYERED`，可选 `WS_EX_TRANSPARENT`（点击穿透），不抢焦点。
  * 快捷键：`Ctrl+Shift+G` 显示/隐藏；`Ctrl+Shift+C` 复制 glyphs。
  * 位置/透明度/缩放记忆在设置里；支持多显示器与高 DPI。
* **渲染两条路径（决策 D8）**：
  * **网页内浮窗**：浏览器 `<canvas>` + WebGL `EXT_texture_compression_bptc` 直读 BC7 DDS（与 Shipwright `viewer.js:56-126` 同一手法，零 CPU 解码）。
  * **独立浮窗**：构建期把 16 张 BC7 一次性转成 PNG（`tools/dds.py` 已预留接口；BC7 解码器列为 M5 任务），运行时只读 PNG。
  * 兜底：无论哪条路，都提供"复制 glyph 串/坐标"的文本路径。
* **为什么不做热传送**：需要进程内调用引擎（版本绑定、崩溃风险）；浮窗方案零风险、零注入，且玩家本来就要走传送门。
* **验收**：随便给一个已知坐标，12 个符文与游戏内传送门界面一致（用 `stations.jsonl` 里 122 个已知地址抽查 5 个）；浮窗在无边框窗口模式下可见。

## F11 本星系船池 ✅
* **目的**：进星系前就知道这里会有什么船。
* **输出**：`ships[]`（kind/type/model/seed/class/subtype）+ 拦截机种子 + dissonant。
* **界面**：表格，按 kind 分组（空间站/货船队/护卫舰/哨兵/海盗/虫群/特殊）；每行可"预览"（L1）与"复制种子"。
* **实现**：`systemgen` + `aiships`（实测 50 条/系统，含 `BIGGS`=corvette）。
* **验收**：与游戏内实际刷出的船型逐项一致（用 dissonant 星系抽查拦截机种子）。

## F12 导出与分享 ✅/🟡
* **导出**：单船 glb（5.3 MB 级）、单船 PNG（多视角拼图）、批量导出（选中 N 个 → zip）。
* **分享码**：`nsh1:` + base64(`type|seed|parts`)；对方粘贴即还原预览（无需服务器）。
* **验收**：分享码在另一台机器（无游戏文件）也能打开 L0 预览。

## F13 设置 / 诊断 / 日志 🟡
* **设置页分组**：路径（游戏/存档/缓存）、外观（主题/缩放）、行为（写开关、确认、备份保留数）、Live（只读开关、进程内后端需二次同意）、关于（版本/上游 commit/许可）。
* **诊断**：一键自检（上游/数据/存档/游戏/系统生成冒烟/Live 签名），输出可复制的报告。
* **日志**：最近 200 行在页面内可看，可导出。

# 第六部分 运维篇

* **安装**：解压即用（`--onedir`），无管理员权限；首次启动引导选游戏/存档目录。
