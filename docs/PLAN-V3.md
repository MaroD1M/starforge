# 方案 v3（功能全景研判 + 路线图）

> 目标：把 starforge 从"飞船工具"做成**星球 / 飞船 / 生物一体的中文情报台**，
> 每一项功能都要回答三个问题：**数据从哪来**、**会不会随游戏更新失效**、**有没有安全边界**。
> 本文只写有依据的判断；不确定的一律标为"需 R&D 探索"，不写成"已能做"。

---

## 一、先给结论（研判摘要）

1. **我们已有**：按部件/类型搜索飞船种子、真实配色与 3D、行星与星系信息、符文浮窗、
   存档写回（含副本/回滚）、实时模板槽、中文化、零配置。
2. **明显缺口**（对照生态，按价值排序）：
   - **反向定位**：种子 → 它在哪个星系/坐标（Shipwright 的 `locate` 已把生成器反过来跑，我们没接）
   - **船级/属性编辑**：上游 `set_ship_stats` 已支持把任意船改成 S 级并设属性，我们没暴露
   - **星球详情**：天气/资源/植被/颜色（Gagarin 有，但它是**游戏内 DLL** 读实时数据）
   - **生物/同伴**：存档里有完整 `Pets` 数据（30 条实测），但上游**没有**生物生成器
3. **不建议做**：内存直接传送、任意部件摆放、开发者选项开关——见第四节红线。
4. **版本瓶颈的答案**：上游的思路是**运行时从你的游戏里反解**（生成器、exe 地址、pak），
   不是硬编码数据。我们继承这一点：**凡是能解析的不内置快照**，内置的只有"映射表/中文名/图标"。

## 二·五、已实测的两项 P0（真机数据，不是纸面判断）

**1. 种子 → 星系反向定位（上游 `locate`，我们直接可用）**

```
本星系 UA 0x10400F19BDCE5（glyphs 1104F19BDCE5）
  船种子 0x494CE787241EBCB2 → 1 个候选，0.0 秒
    coords 04E4:0070:01BC:0104 · glyphs 1104F19BDCE5 · 命中本星系 ✅
  船种子 0x2E0EEC6F935C378C → 1 个候选，0.0 秒 · 同样命中 ✅
```
→ 说明"搜到种子后告诉我在哪"**接线即可用**（注意：少数种子可能反解为空，需给出原因文案）。

**2. 船级改成 S（上游 `set_ship_stats` + 读回核对）**

```
槽位 2 当前 S 级
  写 C → 读回 C 级 | 属性 [78.7, 30.5, 44.5]        （超光速项在非 S 级不显示）
  写 S → 读回 S 级 | 属性 [78.7, 30.5, 8.7, 44.5]
船数一致: True | 其它船种子未变: True
```
→ 双向可写、作用域正确、不影响其它船。接入时沿用现有"备份/原子写/读回/回滚"。

## 三、你点名的诉求：逐项研判

### ① 按部件/类型/颜色生成预览与种子 —— **已有，需补"颜色筛选"**

- 现状：部件 + 类型 + 真实配色渲染；颜色来自 `textures.ship_look(seed)`。
- 缺口：**按颜色搜索**（例如"只要黄+黑"）。可行：颜色由种子推导 → 搜索时对命中种子算配色再过滤，
  代价是过滤在搜索后做（命中率低时慢）。验收：选 2 个颜色，10 秒内出 ≥3 个结果。

### ② 按星球类型/规则筛星球并提供坐标/符文 —— **核心可行，且不需要读内存**

- **关键认知**：星球不是"内存里有什么"，而是**种子决定**。上游用 unicorn 跑游戏自己的行星生成器
  （`systemgen`），所以我们能像 Gagarin 一样**离线扫描银河**，不需要注入。
- 现状：只能看当前星系（`systemgen` 跑一次 ~0.2s 热）。
- 要做：
  1. 批量扫描邻近星系（并行 4 核），筛选条件先做**能稳定拿到的**：生物群系/子类型、哨兵、行星数、
      dissonant（拦截机）、种族/经济/冲突（星系级）。
  2. 结果 → UA → 12 符文（已有 `glyphs` 链路）→ 浮窗显示 + 复制。
  3. **天气/资源/植被/颜色**：需要多调几个生成器函数，属 **R&D spike**（见第六节 P1）。
- 验收：给定"茂盛 + 无哨兵 + 有拦截机"，扫 200 个星系，5 分钟内出结果并可一键复制符文。

### ③ 直接传送 / 浮窗显示符文 —— **传送不做，符文做到底**

- 传送 = 改写玩家位置/星系（内存或存档）。风险：单存档损坏、与多人模式冲突、每次更新都失效。
- 我们的替代：**符文浮窗**（已实现，置顶条 + 可点击穿透）+ 一键复制 12 字符地址；
  以后可加"在游戏里打开星系图并高亮目标"的**只读**辅助（不做位置写入）。
- 验收：从任意结果一键出符文条，贴在游戏上方，`Esc` 关闭。

### ④ 扫本星系/邻近星系的船，并"直接改成 S 级" —— **可做，改在存档里**

- 扫描：上游 `systemgen` 给的船池（已验证 50 条/星系，含类型/模型/种子）。邻近星系 = 多跑几个 UA。
- 改 S 级：上游 `ships.set_ship_stats(readable, slot, ship_class="S", values=…)` 现成。
  安全做法：**只改存档、先备份、写完读回核对**（与现有写回同一套机制）。
- 注意：改的是**这艘船**，不是"让它刷成 S"；属性上界由生成器决定，可给合理上限提示。
- 验收：选中任意船 → 改 S → 重新读档显示 S 且属性在范围内；失败自动回滚。

### ⑤ 一键扫描整个星球的矿物/生物 —— **外部应用做不到"扫"，但能查"有什么"**

- Gagarin 的"Scan planet"是**调用游戏扫描函数并发奖励**，必须在游戏内。
- 我们能做的替代（有价值且安全）：
  1. 行星**资源/植物/动物清单**（来自生成器的行星属性，需 R&D spike 确认字段可得）。
  2. "这星球有什么值得去"：生物群系 + 哨兵器 + 资源 + 是否有拦截机 → 生成**前往理由摘要**。
- 明确不做：伪造扫描奖励、写入已发现列表。

### ⑥ 搜索特定生物伙伴及属性 —— **可做（R&D 后），数据基础已确认**

- 实证：存档 `PlayerStateData.Pets` 有 30 条，每条含 `CreatureID`(`^PLANTCAT`)、`Descriptors`
  （`^_BODY_PLANT`/`^_SHAPE_XRARE`/`^_HEAD_PLANT1`/`^_MESH_PLANT`）、`CreatureSeed`、`SpeciesSeed`、
  `GenusSeed`、`Scale`、`Biome`、`CreatureType`、`Predator` 等 —— 与飞船同构的"描述符 + 种子"结构。
- 社区已解决同类问题：NMSCD 的 `creature.nmscd.com/#/builder` 能预览生物；
  `laanp/NMS-Creature-Builder` 用 Excel 编辑宠物字段（配合 goatfungus/NMSSaveEditor 导入）。
- 缺的是**生成器**：上游没有生物生成器。要做：
  1. 找到生物描述符根（`MODELS/.../CREATURES/**.DESCRIPTOR.MBIN`）并跑通建模 → 3D 预览；
  2. 用 `Descriptors` 组合做筛选（体型/头/颜色），再搜种子；
  3. 写回 = 存档 `Pets[]` 字段编辑（同写回机制）。
- 判定：**可行但工作量大**（一个新生成器 + 一套 UI），列为 P2，先做"读到已有同伴 + 3D 预览"，
  再做"按外观搜索"。

### ⑦ 集成星球/飞船/生物 + 中文化 + 现代界面 + 游戏元素 —— **该做，且是产品主线**

- 信息架构：`搜飞船 / 星球 / 生物 / 我的存档 / 设置`（新增"生物"页，先做"我的同伴"）。
- 中文化：已建立词表体系（`zh.py`），新增字段沿用；专有名词保留英文原名在 tooltip。
- 游戏元素：配色沿用 NMS 的橙/青/紫点缀、圆角卡片、符文图标、扫描线动效（轻量，不影响性能）。
- 内置 vs 解析：中文词表/图标/映射表内置（小、稳定）；几何/贴图/生成器**全部解析游戏资源**。

### ⑧ 避免版本更新瓶颈 —— **工程策略（已有实践 + 待补）**

| 做法 | 现状 |
|---|---|
| 生成器/地址运行时从游戏反解（不硬编码） | ✅ 继承上游 |
| pak 路径与文件名按需搜索、容忍缺失 | ✅ |
| 能力自检 + 降级（缺什么就少一个功能，不崩） | ✅ `selfcheck`/`webcheck`/`/api/textures/status` |
| 中文词表与游戏版本无关（纯映射） | ✅ |
| 新版本适配清单（版本号 + 失效点 + 降级） | ❌ 待补：`docs/COMPAT.md` |

## 四、红线（明确不做，并给出替代）

| 不做 | 原因 | 替代 |
|---|---|---|
| 内存传送（改玩家坐标） | 破坏存档、多人冲突、每次更新失效 | 符文浮窗 + 复制地址 |
| 任意部件摆放 / 移除建造限制 | 会写坏存档结构，且属 Gagarin 专长 | 不涉及 |
| 开发者选项开关（无敌/免费等） | 同上，且改变游戏体验 | 不涉及 |
| 伪造扫描奖励 | 篡改进度与货币 | 只给"有什么好看"的信息 |
| 自动改存档而不备份 | 不可接受 | 备份+原子写+读回+回滚 |

## 五、界面规范（v3 打磨要点）

1. **信息层级**：一屏三栏不变；新增"生物"页；详情面板固定"预览 / 属性 / 操作"三段。
2. **一致性**：所有实体（船/星/生物）都用同一种卡片与同一套操作（复制/收藏/导出/写回）。
3. **中文与原名**：主标题中文，原名进 tooltip；数字与编号保留原文。
4. **空态/加载**：任何等待都显示"正在做什么 + 已用时"；任何失败都给下一步按钮。
5. **键盘**：`Ctrl+Enter` 搜索、`j/k` 切换、`1–4` 视角、`Esc` 关弹层、`/` 聚焦过滤框。
6. **性能预算**：首屏 < 1.5s（预热后）；缩略图后台预取；列表 60 帧滚动。

## 六、路线图与验收

### P0（下一版就能交，2–3 轮）
1. **种子反向定位**：`seed → 星系/坐标/符文`（接 `locate`），结果可直接出符文条。
   验收：任意存档船种子 → 1 秒内给出候选星系（无候选时说明原因）。
2. **船级/属性编辑**：改 S + 属性滑块（带上界提示），备份/核对/回滚。
3. **星球页字段补全（能拿到的部分）**：星河经济/冲突/种族、行星 dissonant 标记、星系船池全量。

### P1（需要 spike，1–2 周量级）
4. **行星天气/资源/植被/颜色**：多调生成器函数，逐项验证可得性；拿不到就明确标注"需游戏内"。
5. **邻近星系批量扫描 + 保存筛选预设**（含"目标：茂盛+无哨兵+拦截机"这类组合）。
6. **贴图落地**：真机确认材质描述符可得后，把 DDS 交给 WebGL（压缩纹理）+ GLB 内嵌 PNG。

### P2（产品化扩展）
7. **生物页**：先"我的同伴"（读 `Pets[]` + 3D 预览），再"按外观搜索 + 写回"。
8. **收藏/设计分享**：已有雏形，补"一键导入社区码"。
9. **文档与兼容矩阵**：`docs/COMPAT.md`（游戏版本 → 哪些功能可用）。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 游戏更新改了生成器/地址 | 搜索/预览失效 | 能力自检 + 明确报错 + 降级到"存档/图标"模式 |
| pak 结构调整 | 几何/贴图读不到 | 路径模糊匹配 + 失败提示"这版游戏暂不支持 3D" |
| 生物生成器不确定 | P2 延期 | 先只做"读已有同伴"，不阻塞主线 |
| 写存档出错 | 玩家进度 | 三重保护（备份/原子/读回/回滚）+ 默认关闭写入 |
| 包体积膨胀 | 下载慢 | 单 exe + 排除测试模块（已做，169MB→84MB） |

---

## 八、下一步（等你确认优先级）

我的建议顺序：**P0-1 反向定位 → P0-2 改 S → P1-4 行星字段 spike → P2-7 生物**。
其中只有 P1-4 和 P2-7 是"可能拿不到"的；其余都有上游现成能力，属于接线与打磨。
